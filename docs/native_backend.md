# 不依赖 g++ 的原生后端

字符串热路径进一步优化：字符串向量元素之间赋值直接复制内部文本引用，不为中间值登记临时根；两端容器和副作用求值顺序仍受保护。split_vector 与两种 join 的字面量分隔符直接使用静态字节，读取稳定变量时借用其句柄。字符串拼接对字面量采用直接入口，对安全的只读操作数借用；有副作用的后续表达式仍保留前一个值的快照。UTF-8 切片一次完整验证并记录字符边界，保留无效编码和越界错误语义。

已知无用户回调的只读字符串操作还可直接借用稳定 vector<str> 元素。`dictionary.get/contains(values, left + right)` 在两个字符串分量均稳定时使用专用查询入口：短复合键在 256 字节栈缓冲中构造查询视图，长键分配临时缓冲，沿用原来的哈希及相等规则；不创建 TX 拼接字符串句柄，并借用稳定的字典字段。缺键 get 返回 none，contains 仍区分缺键与存储的 none。有副作用的键表达式保留原求值与快照路径。

类型化 `vector<int/float/bool/str>` 使用 C++23 `std::vector` 保存连续元素，通过 TX 自有 `vector_view` ABI 暴露数据、长度与容量；LLVM 不访问标准库私有布局。取得容器视图后，下标边界检查和数值元素读写生成直接指令，不逐元素装箱。字符串向量存储共享不可变文本引用，split_vector/join 不经过中间异构数组。容器本身在旧字段/any ABI 中仍保存为一个共享值句柄。完整规则与限制见 [类型化 vector](typed_vectors.md)。

txc 的默认编译路径将类型检查后的 AST 转成 LLVM IR，再由随 TX 分发的 `clang.exe` 生成 Windows x64 COFF 目标文件，最后调用同目录 `link/ld.exe` 链接运行时库和标准库，得到原生 `.exe`。构建 txc 及运行时库仍使用 C++23 编译器；交付给用户的完整 `tx/` 目录不要求用户安装 g++、LLVM 或链接器。

构建脚本从构建机的 LLVM 工具包复制 `clang.exe` 和仓库中的 LLVM 许可证文本；运行时只用它以 `-O3` 将 LLVM IR 编成目标文件。运行时、标准库及其 C ABI 包装位于 `src/backend/cpp/` 和 `src/stdlib/`。整数加、减、乘、取负及循环计数器递增使用 LLVM 内联溢出检查，正常路径无需调用 C ABI；溢出时调用原有运行时函数报告中文错误。有限且位于 int64 范围内的 float 转 int 也由 LLVM 直接生成，越界和 NaN 仍由原运行时报告中文错误。字符串和复合值句柄在作用域退出及函数返回时释放；复合值默认复制共享引用，仅 `deep_copy` 递归复制对象图。运行时错误退出前清理仍存活的句柄，使可正常析构的类对象执行 `deinit`；不可达的循环对象由[循环回收器](garbage_collection.md)处理。

语义分析已确定的标准库目标、重载和参数类型在代码生成时映射为对应的类型化 C ABI；普通调用不再将参数逐个装入 `std::any`，也不在运行时按函数名查找目标。没有 `*`、`**` 展开的命名实参同样在编译期排到形参位置，并保持实参从左到右求值。普通位置实参后各有一次 `*`、`**` 展开且目标收集可变参数时，编译器直接传递已确定的普通实参；运行时验证动态展开类型、字典键和冲突，并分别复制可变参数容器，避免构造通用绑定结果数组。静态类型已知的数组索引和字典键走专用入口，编译期字符串字面量键直接传给字典索引；静态类型基础字段按确定的槽位读写，动态值仍保留类型与越界检查。同一方法入口块首次取得的 `self` 标量字段地址可在后续代码块复用；`self` 不可重新绑定，字段存储也不会在方法执行期间改变槽位。调用接收者和不会重新绑定的引用参数借用调用方句柄；字符串参数只在后续实参不会修改原变量时借用。临时值仍按所有权释放。结构体的两个字段以内联空间存放，更多字段使用动态存储；类与结构体的静态名称元数据不再每个对象复制。运行时把句柄的链表节点与值放在同一次分配内，释放时常数时间摘除节点，错误退出仍按创建顺序逆序清理。循环回收安全点在可能创建复合对象或释放动态引用的语句后保留，纯数值路径不再每句轮询。展开内容、`any` 的实际值、文件系统状态及运算错误仍在运行时处理。

数组的普通定长创建直接构造目标存储，不再先创建一个默认空数组。静态 `array` 变量在持有原有共享句柄的同时缓存数组引用，长度、索引读写与标量初始化通过专用 C ABI 使用该引用；变量重新绑定时同步刷新引用。已知写入值为整数、浮点数、布尔值或字符串时，普通数组和结构体成员数组通过专用入口写入，避免把纯值数组登记为可能成环的对象。可证明来源和目标稳定的元素间复制直接读取源槽位，并按实际值决定是否登记目标数组。已知目标是 `int`、`float` 或 `str` 的数组元素读取通过单个专用入口完成对应转换，避免先取元素地址再调用转换入口；字符串结果仍创建独立句柄。静态 `dict` 变量也缓存字典引用，字面量或变量键的读取直接从该引用查找；字符串字面量键免去键对象构造，目标明确为 `int`、`float` 或 `str` 时通过专用入口完成查找与转换，重新绑定时刷新引用。字典标准库的字符串键查询、删除及静态字符串键的标量写入直接传递字符串，减少键与值的临时装箱。其他可能有副作用的键表达式沿用通用索引路径。`len` 和 `is_none` 对可保持拥有者存活的变量或元素借用地址。解包及遍历把 `none`、整数、浮点数和布尔值保存为标量快照，遇到其他类型仍复制独立句柄；一般 `any` 用途才将标量快照装箱。生成的正常路径直接检查 C ABI 状态码，只有非零状态进入原有错误处理。

字符串句柄共享不可变文本，普通复制只增加持有计数，写入数组或字典等值容器时仍复制字符串内容以保留值语义。只读标准库函数使用 `string_view`，不会在 C++ 实现入口按值复制文本。字符串常量参与的比较、查找、切分与替换可直接把静态字节传给专用 ABI；值为字符串变量且后续实参不会修改它时直接借用句柄。字符串替换向结果缓冲区顺序追加，避免反复移动原文本的后缀；`split` 和 `join` 预留所需容量，减少动态扩容。UTF-8 字符位置和原有错误规则保持不变。

对于长度不超过 32、初值与后续写入均为标量或 `none`、且所有用途均可证明没有别名或逃逸的局部数组，后端在函数栈上使用带类型标记的固定槽位。长度、判空、标量索引、解包和遍历从这些槽位生成代码，越界和错误类型仍沿用运行时中文错误。其他数组保留通用共享表示和动态元素语义；通用 `any` 仍需要 `std::any` 句柄，因此专用引用不等于全面替换动态值表示。[数组优化行为样例](../examples/array_fast_paths.tx)覆盖局部槽位、元素快照、共享别名、补齐初始化及重新绑定。

函数体顶层声明、无初值、长度在运行时确定且同样可证明不逃逸的局部标量数组，使用独立连续槽位；创建时验证长度，索引仍检查越界，作用域结束时释放存储。这个路径覆盖动态长度的判空和标量读写，例如[外部算法负载记录](../benchmarks/not_yet_on_stage.md)中的 `used` 数组。返回、传参、别名、混合类型写入等无法证明安全的用途继续使用通用数组。

随机数状态仍按线程隔离。生成函数在首次实际调用随机数库时获取当前线程的状态句柄，并在该次函数调用内复用；`seed`、整数随机数和浮点随机数共用此句柄。这样避免在循环每轮通过 MinGW 的线程局部访问辅助函数查找状态。C ABI 的线程局部错误文本只在失败时写入并读取，成功路径不再清空它；生成程序仅根据非零状态读取错误文本。

发行时必须保留整个 `tx/` 目录。链接器、启动文件和链接库位于 `tx/link/`；编译器和目标程序所需的 MinGW 运行时 DLL 会随工具或目标程序放置。默认输出仍为 `tx_build/<源码名>.exe`，`-o` 可指定位置。调试后端时可用 `txc emit-llvm <源码.tx> [-o <输出.ll>]` 查看中间 LLVM IR。

当前目标平台为 Windows x64。普通源码模块和仓库提供的标准库二进制接口均可编译；没有实现的其他二进制 `.txh` 函数会在编译时报错。本机验证曾将 PATH 收窄到 Windows 系统目录，再用交付的 `tx/` 编译并运行整数、递归、重载、数据类型、终端 I/O 和文件编码示例。此验证说明编译过程不调用 PATH 中的 g++；完整发行目录仍需要在另一台干净机器上验收。

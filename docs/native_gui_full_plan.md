# 跨平台自绘 GUI 完整版实施契约

算法研究与公开规范见 [自研 GUI 算法与规范依据](native_gui_research.md)。用户允许查阅论文，
但研究参考不改变全部自行实现的边界。

## 目标与完成定义

用户已选择独立 GUI 库，并明确要求 Windows 与 Linux 的完整版。当前的 Windows 基础控件
只是实现过程，不是最终交付。最终 GUI 必须由同一套 `.tx` 业务源码构建并运行于双平台。
禁止把只声明的接口、空实现、平台不支持错误或仅编译通过计为已完成。

“自绘”指所有普通控件、弹出菜单、滚动条和布局由库维护与绘制，窗口内不使用系统
Button/Edit/ListView/TreeView 等子控件。操作系统窗口管理、输入法、剪贴板、
文件选择器和辅助技术协议通过薄平台适配层访问。

用户进一步明确要求自行实现，不引入 Qt、GTK、SDL、ImGui 等第三方 GUI/窗口框架。
控件、布局、事件分发、焦点、编辑模型、绘制组织及数据模型均由本项目实现。
绘图、字体解析和文字排版也全部自行实现：最终实现不使用 Direct2D、DirectWrite、
FreeType、HarfBuzz、Pango、Cairo、Skia 或 ICU 代替这些模块。字体文件和 Unicode 标准数据
是输入数据，不是外部实现代码。平台层只连接窗口协议、输入、像素提交及必要系统服务。

## 结构

- 公共接口：`tx/stdlib/native_gui.txh`，具体不透明资源类型与固定记录。
- C ABI：`src/backend/cpp/native_gui_*`，静态签名展开，不做字符串方法查找。
- 控件与布局：`src/stdlib/native_gui/`，平台无关状态、测量、排列、命中、事件和模型。
- 图像核心：自研像素缓冲、路径展平、覆盖率光栅化、裁剪、合成、图像采样与脏区提交。
- 文字核心：自研字体文件解析、轮廓光栅化、字形缓存、Unicode 分段、布局、命中和光标映射。
- 平台适配：自行实现 Windows 与 Linux 窗口、输入、像素提交、剪贴板与辅助技术连接层。
- 驱动/发行：Windows 与 Linux 选源、运行库和平台插件打包；不要求终端用户安装 SDK。

独立 GUI 不要求 Linux 导入只支持 Windows 的 `graphics.txh`。应用、窗口、事件循环与
像素提交使用独立跨平台入口；现有 graphics/gui 保留兼容性，不能靠取消导入检查伪装支持。

## 实施规则

先抽离公共核心，再重构当前 Windows 原型，并接入自行实现的 Linux 适配，避免长期维护两套交互算法。
每个工作包补齐对应契约、示例及最小必要验证；不重复运行不相关标准库全量测试。
禁止使用外部 GUI、窗口或控件框架替代本项目的实现，也不以改名或包一层 ABI 规避这一约束。

关键动态状态包括鼠标、IME、操作系统焦点与外部文件操作；控件静态类型、调用重载和
资源身份仍由编译器与直接 ABI 保证。公共文本位置以 Unicode 标量索引表达，编辑导航
按字素边界移动，平台 UTF-16/UTF-8 偏移只存在于适配层。

## 本次续接：Linux 输入法

先完成上次中断的 XIM 接入：重新对照 X.Org Input Method Protocol 的传输表 D.3、
输入上下文属性、事件掩码、预编辑与同步消息。由库自行编码协议；输入法服务只提供
组合输入与候选，不承担控件绘制、字体解析或文字排版。

- 兼容规范列出的六种 X 传输组合；对超长、截断和非法上下文消息给出明确诊断。
- 所有返回应用的输入事件都构成交付边界，应用处理焦点/光标后才继续发送排队输入。
- 聚焦切换、只读/密码切换和失焦应重置旧组合，迟到的旧提交不能进入新编辑位置。
- 用独立协议对端通过真实 X11 连接验证握手、候选位置、预编辑、提交、同步与取消。
  此项不代替真实中文输入法服务及桌面人工验收，后者单独记录。

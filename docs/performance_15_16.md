# 剩余库内热点与构建评估契约

本轮对应性能计划 15–16。公开语法、接口、数值格式、错误类别、Unicode 长度、引用和迭代器消费规则保持不变。

- 十六进制输出先检查 `2 * size` 的 int64 和目标字符串容量上限，再一次确定目标大小，直接写入小写字符。解码仍接受大小写，仍拒绝奇数长度、空白、NUL 和非十六进制字符；先检查全部字符，再构造一个输出缓冲，失败不发布部分 bytes。
- UTF-8 编解码保留严格校验、BOM 和长度限制。当前 str 是带独立引用计数的 `std::string`，bytes 是 `shared_ptr<const vector<uint8_t>>`，不能通过别名指针安全地互换拥有者。保留已有一次复制路径；不为共享内容更换全部 bytes/str 表示。其他编码仍需实际转换。
- statistics 的向量入口已经一次恢复连续存储；有限值检查依赖每个元素，不能提升。保留 long double Neumaier 累计、计数和范围检查，不拆块或调整累加顺序。迭代器在检查当前值前推进，报错后继续读取下一项。
- 数值转换先检查优化后的机器码。已有整数十进制转换和浮点 `to_chars/from_chars` 不重写；外围句柄工作与转换核心分别记录。
- 第 16 项以最终程序的机器码为依据。普通 GCC 标准库、clang 生成程序和 GNU ld 的路径保持可用；仅在端到端收益足以支持工具链迁移时才启用 LTO。独立探针不等于全部第三方库、异常、线程或原生回调已通过迁移验收。

验证记录放在 `benchmarks/performance_optimization_15_16_2026-09-29/`。先冻结旧包和基准，再构建、定向行为检查、同轮测量；历史未通过项仍单列，不将实施复选框当作性能达标证明。

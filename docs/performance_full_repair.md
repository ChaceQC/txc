## 定位证据与验证

- 原 LLVM IR 在解构声明后立即调用 `txrt_value_snapshot_box`；修复后
  `unpack_snapshot` 保持标量，真实重新解构赋值仍有正确的覆盖行为。
- 原 `sync.guard_get` 被统一标为修改实参，使嵌套读取复制前一个 guard；
  修正后直接借用。锁取得仍分配拥有状态。
- TLS 临时计时显示，证书验证约 12～32 ms/次，实际握手约 3～5 ms/次。
  复用引擎后，同一输入后续验证约 0.2～0.3 ms。首次构建仍完整执行。
  正式源码没有阶段打印；这些数据仅用于定位，网络结果以配对样本为准。
- 已通过一次同步、通道、闭包、日志、格式化、正则、JSON/serde、图复制、
  GC/复活和编码行为检查。新增检查覆盖数组快照/重赋值、原子溢出后状态、
  关闭通道取值、整数填充及空/短/长环境变量。
- X.509 检查包括缓存命中后换主机名/用途、移除中间证书/根、错误后恢复，
  以及既有过期、未来、非 CA、PKCS#12 互操作和资源增长检查。
- 旧跨线程 ABI 测试仍声明返回 `std::string*`，已改为现有文本句柄类型；
  跨线程原始错误和嵌套等待检查随后通过。后续只补跑受借用变化影响的
  格式化/decimal/均值及此前未完成的数据库、ABI 和封包检查。

## 尚存的性能差距

- 无竞争锁仍创建 guard 的拥有状态、共享所有权及可关闭身份。本轮删除了
  冗余复制，没有实现局部 guard 的无堆分配表示。
- 析构、通用 GC、动态参数展开与深拷贝仍有拥有关系、图追踪和参数包构造
  成本。没有以显式 close 或仅删除自环代替通用语义。
- 格式化、编码、短容器和字符串转换仍有 ABI 与结果分配成本。整数追加和
  借用改动不等于所有格式化基准都有可测加速。
- HTTP 便捷 API 保留每次会话创建、自动代理与单次请求隔离，没有引入隐式
  全局会话池。跨客户端库的端到端倍率不直接等同包装层缺陷。
- 接近 1 倍及亚毫秒项目不宣称加速；大 map 波动另做校准，未改善的结果保留。

完成的是整份清单的核对、已确认冗余路径修复及相关验证；**不能据此声称全部
负载已低于 C++ 的三倍，也不能把尚存成本当成已经完成的后续优化。**

# 线程接口与静态边界

`thread.txh` 提供 `spawn<T>(fn()->T)`、`join<T>`、`detach<T>` 和 `id<T>`。回调结果 `T` 可以是 `void` 或满足 `Send` 的类型；文本及复合值在工作线程退出前复制到线程结果状态，`join` 在调用线程建立本地句柄。`spawn` 的回调必须是顶层 TX 函数，或在调用处直接用 `bind` 构造。标量、不可变 `str/bytes` 和有同步保证的控制句柄按值捕获；可变 Send 容器/结构体必须以 `move(value)` 唯一转交。语义分析递归检查捕获字段/元素，拒绝普通别名、逃逸值、非 Send 句柄和其他闭包来源。

`join` 等待工作线程结束，返回静态结果类型；线程中的原始错误类别、代码、消息和 TX 调用栈交给 `join` 调用方。一次句柄只能 `join` 或 `detach` 一次，所有普通别名共享状态。`detach` 后错误会进入全局回收队列；`take_detached_error()` 取出一条 `code: message`，空字符串表示队列为空。最后一个句柄离开作用域而没有显式处理时自动 detach，工作线程结束后同样回收错误。`id` 在 join 或 detach 前读取线程标识；标识仅适合本进程内诊断，之后调用报 `invalid_state`。

工作线程各自初始化运行时上下文。闭包边界复制对象图值并在目标线程建立本地 C ABI 句柄；句柄不会被另一个线程直接注销。工作线程退出时清理本地句柄并回收本地循环；主线程在 `join` 后尝试全局对象图回收。Send/Sync、唯一移动及最小线程/锁集成已按[2.6 规则](send_sync.md)验收；第 10 节线程生命周期、通道与同步原语的定向验收见[标准库计划](standard_library_plan.md#10-线程任务与进程间通信)。

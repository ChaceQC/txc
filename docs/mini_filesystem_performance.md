# mini-filesystem 性能优化记录

最新状态：类型化 vector 和后续字符串热路径优化均已落地，见本文末尾两节；前面的两批结果保留为历史记录。

最新同轮五语言复测已完成，采用每组预运行两次、正式运行十七次的中位数，见 [五语言比较](../benchmarks/mini_filesystem.md#vector-与字符串优化后的同轮五语言比较)。本文下面的七次采样表用于 TX 前后版本对照，勿与新一轮的其他语言结果混用。

2026-09-25。负载位于 `E:\Project\problems\mini-filesystem`，比较口径是五种程序预读全部命令后，从文件系统初始化到执行完成并保存答案的内部耗时；输入、输出及进程启动不计入。

## 结果

当前 TX 编译器与修改后的 `src/mini_fs.tx` 配合，在同一台 Windows 机器上对五组 `q=2000` 数据预热两轮，再轮换执行七轮。单位为毫秒，表中为内部耗时中位数。基准列来自本仓库已有的[原始记录](../benchmarks/mini_filesystem.md)，其采样次数为 17；两列的算法和采样次数不同，不能把全部差值算作编译器收益。

| 数据 | C++ 原记录 | JavaScript 原记录 | TX 原记录 | TX 当前 | 当前 TX / JavaScript |
| --- | ---: | ---: | ---: | ---: | ---: |
| fanout-2000 | 1.692 | 5.062 | 89.221 | 12.108 | 2.39 倍 |
| deep-pwd-2000 | 15.073 | 9.737 | 134.753 | 36.768 | 3.78 倍 |
| linklong-2000 | 112.365 | 119.421 | 1112.896 | 45.039 | 0.38 倍 |
| moves-2000 | 1.057 | 2.056 | 53.594 | 5.080 | 2.47 倍 |

题目计时解通过全部 44 组正式数据；普通解也在代表数据上与答案一致。字符串别名、循环回收、错误退出清理、字典和标准库示例做了定向验证。`cycle_resurrection.tx` 之前用可被后端消去的空局部数组触发回收，现改为确实分配的复合数组，输出恢复为 `victim deinit`、`7`。

## 已落实的改动

- 数组写入已知的整数、浮点数、布尔值和字符串时走专用 ABI；数组元素间复制动态值时按实际类型决定是否登记循环回收器。字典写入纯值时也延迟登记，通用可写槽位保留保守登记。
- 字符串句柄共享不可变文本，复制只增加持有计数；只读标准库函数使用 `string_view`。字符串字面量比较及常用只读调用直接使用静态字节；字符串替换、切分和连接减少中间复制与扩容。
- 活跃句柄的元数据与值同次分配，链表摘除为常数时间，错误退出仍可清理活跃句柄。字符串键的字典查询、删除及标量写入使用直接入口。
- `mini_fs.tx` 在创建链接时只对已有语义允许的前导 `./` 做词法压缩，单个普通名字直接解析，父编号前缀在创建节点时保存。这些缓存不保存链接最终指向的对象，MOVE 后的相对链接仍从新父目录解析。

题目层缓存和编译器改动各有收益。在尚未改动题解的中间版本，长链接已由约 1105 ms 降至约 222 ms；此后题解快速路径使它继续下降。当前结果同时包含两者，不应作为“TX 对所有程序都快了 20 多倍”的结论。

## 仍有的短负载差距

四组短负载仍比原 JavaScript 记录慢约 2.4～3.8 倍。插桩统计显示，在加入字符串共享后，`fanout-2000` 的计时区间仍有约 12 万次、`deep-pwd-2000` 约 39 万次经静态链接代码发出的 `operator new` 请求。该计数不含 DLL 内部未拦截的请求；详细插桩会扰动耗时，只用调用次数判断热点。

这些请求主要来自通用 `array` 的 `vector<any>` 表示：把字符串放入数组会复制并装箱。`deep-pwd` 每次 PWD 沿父链创建名字数组，重复这一操作；`fanout`、`moves` 与 `random` 还频繁解析路径并访问通用字典。TX 题解使用全局字符串复合键，原 C++ 解使用每目录名字映射，各语言实现的分配次数也不相同。

曾尝试让 TX 题解使用每目录独立字典；当前语言需要从通用数组取出目录类对象并做运行时转换，五组负载全部回退，因此已撤回。另一次尝试把结构体字段定位、数组读取和转换合成一个异常包装入口，也使 `fanout` 从约 11.8 ms 升至 30.5 ms，已撤回。当前已有的快速地址读取组合更适合这个负载。

若继续追求与 C++ 或 JavaScript 接近的短负载成绩，需要为跨函数、存于结构体中的同构数组和字典建立类型化表示，并在后端生成原生元素访问；这涉及新的类型规则和容器 ABI。按仓库约定，应先写明语法、共享别名、错误转换及跨模块布局，再实施。现有 `array`、`dict` 保持异构动态语义，不能仅以这道题的使用方式推断它们总是 `array<int>` 或 `dict<str,int>`。

诊断用 LLVM IR、程序和调用统计工具保留在被 Git 忽略的 `tx_build/mini_fs_analysis/`。正式编译器和静态库由 `scripts/build.ps1` 构建到 `tx/`。

## 类型化 vector 落地

2026-09-25 新增 `vector<int>`、`vector<float>`、`vector<bool>`、`vector<str>`，支持跨函数与模块、结构体和类字段。连续元素存储由 std::vector 管理；数值索引生成直接 load/store，字符串向量复制不可变文本引用。旧 array/dict 的动态语义保留。

mini_fs 的六个节点属性数组、命令数组、结果数组以及路径分量均已迁移；路径解析、链接压缩、复合字符串键和 MOVE 逻辑保持原样。普通解与计时解分别通过 44/44 组正式数据。

## 字符串热路径优化

在 vector 版本上继续优化，没有改变 UTF-8 字符位置、字符串值语义及字典键相等规则：

- vector<str> 元素间赋值直接复制内部文本引用，省去中间根句柄的登记/释放；源、目标及索引求值顺序保持不变，临时拥有者保持到赋值完成。
- split_vector、array/vector 两种 join 的字面量分隔符使用静态字节；只读字符串操作借用稳定的变量或向量元素。
- 字符串拼接直接接受字面量，安全操作数使用只读借用；有副作用的后续操作数仍保留前值快照。
- UTF-8 slice 在一次完整验证中定位两个边界，保留对范围外无效编码的诊断，以及无效编码优先于无效范围的错误顺序。
- dictionary.get/contains 的稳定二段字符串键走专用入口，短键使用栈缓冲查询，长键使用临时字符串缓冲，沿用原哈希。题解 child_key 改为直接拼接向量元素；lookup_child 将同一复合键表达式直接交给 dictionary.get，使后端能识别查询。前缀内容、字典结构、路径解析和 MOVE 算法没有变化。

最终同轮测量仍是各预运行两轮、交替执行七轮、中位数、内部计时，单位为毫秒；没有并发构建或插桩。vector 基线为保留的 `after.exe`，字符串版本为 `strings.exe`。本表是新一轮，基线小幅偏离上一节属于运行波动。

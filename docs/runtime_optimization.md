# 运行时公共开销优化

本轮从运行时上下文、诊断栈和错误 ABI 开始，不改变 `.tx` 语法、共享引用、异常类别或析构语义。

第一阶段已于 2026-09-27 完成实现、工具链整体重建和定向验收。三轮同源码对照中，递归从 33.819 ms 降至 0.805 ms，类方法从 57.865 ms 降至 1.694 ms，500 万次随机数从 104 ms 降至 36 ms；原始样本、语义验证和成品哈希见[阶段验收报告](../benchmarks/runtime_context_2026-09-27.md)。

成品已写入 `tx/`；临时 `build/` 的清理被执行工具策略拒绝，目录保留。

## 第一阶段约定

- 每个线程持有一个 `runtime_context`，集中管理错误、诊断栈、存活句柄、循环回收状态和默认随机数生成器。程序入口及原生回调边界获取上下文，普通 TX 函数、方法、虚调用和运算符使用隐式首参数传递上下文。
- 原生访问器使用 `constinit thread_local` 指针缓存已初始化的上下文。拥有上下文的线程局部对象仅在首次访问时初始化并登记析构，避免 MinGW 在每次访问时分别查询初始化守卫和对象存储；成功路径只查询一次 TLS。TX 内部传递指针的路径无需这次查询。
- 诊断帧由生成函数在自身栈上分配，通过上下文中的链表头连接。正常调用只读写指针及源码位置，不扩容诊断容器，也不逐次查询 TLS。错误发生或显式获取栈轨迹时才复制完整快照。
- 上下文的诊断链表头和错误类别、诊断帧的字段布局是内部 C ABI。C++ 使用静态断言验证偏移，LLVM 使用对应的命名类型。兼容指纹覆盖这些定义；编译器、预编译 TX 桥接对象和标准库必须整体重建。
- 可能执行用户回调或析构的 ABI 保留待传播错误检查。明确没有这些能力的标量操作使用独立的叶子操作入口：成功直接返回零，失败记录错误并返回非零，不清空已有错误。
- 默认随机数操作接收运行时上下文，以状态码返回成功或失败，并通过输出参数交付结果。生成程序在确认成功后使用结果，不再额外调用 `txrt_error_status()`。
- 可恢复错误模式下，内部无状态返回调用后的必要检查直接读取已传入上下文的错误类别。原生回调仍负责遵守其边界约定；错误清理期间保留最初错误及其快照。

## 验证与后续范围

定向验证递归/虚调用、错误栈、跨函数异常、闭包回调、析构失败、对象复活和随机数错误；检查生成 IR 与关键二进制路径，并对递归、类方法、随机数做同源码前后对照。记录校验值及样本，避免用与历史不同的程序宣称性能提升。

下一阶段再建立贯穿语义分析和代码生成的调用属性，收敛当前按指令字符串检查错误的逻辑；随后推进容器借用及对象布局、闭包环境、静态 serde 描述和库算法。第一阶段不会将未经证明的容器、回调或析构操作标记为叶子操作。

# 运行时公共开销优化

本轮从运行时上下文、诊断栈和错误 ABI 开始，不改变 `.tx` 语法、共享引用、异常类别或析构语义。

第一阶段已于 2026-09-27 完成实现、工具链整体重建和定向验收。三轮同源码对照中，递归从 33.819 ms 降至 0.805 ms，类方法从 57.865 ms 降至 1.694 ms，500 万次随机数从 104 ms 降至 36 ms；原始样本、语义验证和成品哈希见[阶段验收报告](../benchmarks/runtime_context_2026-09-27.md)。

成品已写入 `tx/`；临时 `build/` 的清理被执行工具策略拒绝，目录保留。

## 第一阶段约定

- 每个线程持有一个 `runtime_context`，集中管理错误、诊断栈、存活句柄、循环回收状态和默认随机数生成器。程序入口及原生回调边界获取上下文，普通 TX 函数、方法、虚调用和运算符使用隐式首参数传递上下文。
- 原生访问器使用 `constinit thread_local` 指针缓存已初始化的上下文。拥有上下文的线程局部对象仅在首次访问时初始化并登记析构，避免 MinGW 在每次访问时分别查询初始化守卫和对象存储；成功路径只查询一次 TLS。TX 内部传递指针的路径无需这次查询。
- 诊断帧由生成函数在自身栈上分配，通过上下文中的链表头连接。正常调用只读写指针及源码位置，不扩容诊断容器，也不逐次查询 TLS。错误发生或显式获取栈轨迹时才复制完整快照。
- 上下文的诊断链表头和错误类别、诊断帧的字段布局是内部 C ABI。C++ 使用静态断言验证偏移，LLVM 使用对应的命名类型。兼容指纹覆盖这些定义；编译器、预编译 TX 桥接对象和标准库必须整体重建。
- 可能执行用户回调或析构的 ABI 保留待传播错误检查。明确没有这些能力的标量操作使用独立的叶子操作入口：成功直接返回零，失败记录错误并返回非零，不清空已有错误。
- 默认随机数操作接收运行时上下文，以状态码返回成功或失败，并通过输出参数交付结果。生成程序在确认成功后使用结果，不再额外调用 `txrt_error_status()`。
- 可恢复错误模式下，内部无状态返回调用后的必要检查直接读取已传入上下文的错误类别。原生回调仍负责遵守其边界约定；错误清理期间保留最初错误及其快照。

## 验证与后续范围

定向验证递归/虚调用、错误栈、跨函数异常、闭包回调、析构失败、对象复活和随机数错误；检查生成 IR 与关键二进制路径，并对递归、类方法、随机数做同源码前后对照。记录校验值及样本，避免用与历史不同的程序宣称性能提升。

后续优化遵循：编译期已知的类型、调用目标、参数关系和常量配置直接用于生成专用代码；运行时只处理实际动态的数据、外部状态和无法证明可省略的检查。

## 第二阶段：调用属性与安全借用（首批已完成）

本阶段先消除容器和高频标准库调用外围的重复工作，不改变语法、共享引用、求值顺序或错误类别。

- 语义分析在已完成重载和类型绑定的调用节点上记录参数持有/借用关系，以及分配、用户回调、用户对象析构、参数修改和参数保存属性。未覆盖的入口采用保守属性，不能仅凭方法名判定安全。
- 已证明调用不会执行用户代码或释放用户对象，且后续实参求值不会使借用失效时，借用局部变量或稳定字段；否则继续持有接收者。接收者仍先于后续实参求值。
- 首批覆盖基础类型的 `map/set/queue/deque/vector` 操作、容器长度、动态字典只读查询和取消状态查询；静态命名实参与位置实参使用相同的借用规则。对象键、自定义比较器、可能析构对象的删除操作继续使用保守路径。
- 动态字典的 `int/float/bool` 键直接传给类型专用 ABI；混合键仍按类型区分，浮点正负零相等，NaN 查询不命中。删除动态值仍保留用户析构错误传播。
- 只有已确认不运行用户代码且不释放用户对象的运行时入口使用叶子错误包装；状态查询不能标为纯函数或常量折叠。

验收以生成代码和相关语义为准：安全容器调用没有临时 `txrt_value_clone`，基础字典键查询没有 `txrt_value_box_*`，危险实参重绑定仍保留持有；验证别名、回调、析构、NaN、错误传播及对应热点负载。只运行这些相关验证。

2026-09-27 已完成编译器、标准库和预编译 TX 桥接对象的重建；新增借用行为与 IR 验证通过，既有容器行为和错误分组 8/8 通过。五项同源码负载的三轮交替对照中位数分别改善约 16.07、35.69、9.49、8.43、8.47 倍；具体负载、原始样本、结构证据、成品指纹和未完成项见[首批验收报告](../benchmarks/call_borrowing_2026-09-27.md)。这些倍率仅代表报告中的固定负载。

## 后续工作顺序

### 继续实施的约束（2026-09-27）

- 向量局部变量和参数缓存稳定的存储头引用，重绑定时同步更新；扩容只更新头中的数据、长度与容量。只有循环体不能修改容器、执行用户代码或释放用户对象时，才提升数据和长度，并使用已证明的遍历范围省略检查。
- serde 的字段、类型、版本、默认值和未知字段策略由编译器生成不可变描述，不再把 schema 编成 JSON 后交给运行时解析。输入的数据校验、重复字段和错误类别保持。
- 字面量 format 在编译期绑定字段与参数，直接生成类型明确的写入操作；动态模板或无法静态绑定的参数展开保留通用入口。实参仍按源码顺序求值，原有运行时格式错误仍可捕获。
- 均值使用独立的稳定累计；文件读取按实际分块增长，UTF-8 路径保留严格校验并消除 UTF-16 中转；regex 工作区复用必须隔离并发和重入。

以上为继续实施的规则，具体完成和验证状态以本轮验收记录为准。

1. 继续扩展 map/set/queue 等类型化内部表示，以及普通索引循环的别名与范围证明；收敛旧的指令字符串错误分类。稳定向量头及满足证明条件的标量 foreach 已完成。
2. 在静态 serde 描述基础上移除编解码的中间动态树；继续处理格式化的复合值、静态参数展开和常量求值，以及常量舍入模式。运行时 schema 解析、基础类型字面量 format 的动态实参容器和已知编码名解析已消除。
3. 调整 decimal 的系数与 scale 表示、按实际使用字段裁剪 regex 结果，并独立处理网络会话生命周期。均值专用稳定累计、文件流分块缓冲、UTF-8 直接校验和 regex 工作区复用已完成。
4. 按剩余热点处理闭包及 bind、内联和跨库优化，再覆盖 bytes、parse、string、random。保留随机状态和序列契约。

各阶段分别记录实现和验证状态，不以部分热点变快替代整份清单的完成验收。

## 本轮继续交付：静态描述、格式化及库内热点

2026-09-27 已更新编译器、标准库和三个预编译 TX 桥接对象。新增稳定向量头、保守 foreach 范围证明、静态 serde 描述、基础类型字面量 format、常量编码名选路，以及均值、UTF-8、文件读取和 regex 工作区优化。

均值使用扩展精度 Neumaier 补偿累计；编译期确认 `long double` 指数范围足以容纳最多 `int64` 个有限 `double` 的和，收尾只除一次。范围不足的平台保留加权均值路径，有限输入、空样本、迭代器推进、结果范围和正负抵消精度继续检查。

9 个相关 TX 行为程序、生成 IR 检查及 2 个原生边界程序通过。后续仅对编码选路和均值的实际修改补跑对应场景。最终三轮同源码交替对照中，向量 foreach、serde JSON、字面量 format、均值和 UTF-8 编码中位数分别改善约 10.17、6.82、5.57、1.25、1.99 倍，限于报告中的固定负载。

完成范围、原始样本、成品指纹与剩余事项见[本轮验收报告](../benchmarks/static_runtime_2026-09-27.md)。

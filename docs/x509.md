# X.509 证书读取与验证

`x509.txh` 使用不可变的 DER `bytes` 表示单张证书，`vector<bytes>` 表示证书集合。`parse_pem` 读取一张或多张 `CERTIFICATE` PEM 块，`parse_der` 校验单张 DER；两个入口都会拒绝空输入、无效编码、尾部数据、超过 1 MiB 的单张证书、超过 16 MiB 的总输入或超过 64 张证书。PEM 不读取私钥块。调用方可用 `file.read_text`/`file.read_bytes` 读取文件后传入。

```tx
struct verification
{
    status: str
    revocation: str
    chain: vector<bytes>
}

def parse_pem(text: str) -> vector<bytes>
def parse_der(data: bytes) -> bytes
def parse_pkcs12(data: bytes, password: secret_bytes) -> vector<bytes>
def pkcs12_private_key(data: bytes, password: secret_bytes) -> secret_bytes
def verify(leaf: bytes, intermediates: vector<bytes>,
           trust_anchors: vector<bytes>, hostname: str, purpose: str,
           system_trust: bool) -> verification
```

`parse_pkcs12` 读取最多 64 张证书，持有私钥的证书排在首位，其余顺序不承诺。`pkcs12_private_key` 从同一包中导出 PKCS#8 DER 到 `secret_bytes`；包中没有私钥或密钥不可导出时失败。密码是 UTF-8 `secret_bytes`，不写入异常或日志；导入期间的临时密码和明文密钥缓冲在释放前擦除。传入的 PKCS#12 `bytes` 仍是普通字节值，不具有秘密缓冲的清零保证；应用应避免将它打印或记录。私钥需按[秘密字节](secret_bytes.md)规则使用和关闭。

`verify` 按当前系统时间构建叶证书到锚的链，返回链的 DER 快照，顺序为叶到根。`purpose` 仅接受 `server_auth`、`client_auth`、`code_signing`；`server_auth` 必须提供非空 `hostname`，其余用途不检查主机名。`system_trust=false` 时只信任传入的自定义锚，`true` 时还信任系统根证书；无锚不会自动放行。中间证书不会因为被传入而取得根信任。`status` 是 `valid`、`not_yet_valid`、`expired`、`hostname_mismatch`、`wrong_purpose`、`unknown_issuer` 或 `invalid_chain`。只有 `valid` 可以用于建立已验证身份，其他状态均为失败。链不完整时 `chain` 只包含实际找到的部分。无效签名、CA 约束及其他链错误归为 `invalid_chain`。

当前入口**不查询 CRL 或 OCSP**，因此每个结果的 `revocation` 均为 `not_checked`，包括 `status=valid` 的结果。调用方不能据此声称证书未被撤销；要求撤销检查的策略必须拒绝此结果，后续 TLS 入口不得静默绕过链或主机名验证。

格式错误抛出 `security_error/invalid_certificate` 或 `invalid_pkcs12`；密码错误或无法解密的包统一为 `security_error/invalid_password_or_data`，不回显秘密值。输入过大为 `security_error/size_limit`，用途、主机名参数不合法为 `security_error/invalid_argument`，平台服务调用失败为 `security_error/operation_failed`，平台尚不支持的入口为 `security_error/unsupported_platform`。证书身份验证失败使用 `verification.status`，供调用方区分原因；它不是格式解析异常。

当前实现使用 Windows CryptoAPI 的证书链引擎、系统根证书存储和仅进程内的 PKCS#12 密钥导入。PKCS#12 使用 `PKCS12_NO_PERSIST_KEY`；密钥关联在同一进程的证书上下文中，导出 PKCS#8 时仅调整该临时密钥句柄的导出策略，随后复制进 `secret_bytes`。系统信任结果随机器与用户证书存储变化；无网络根证书自动更新，也不执行撤销查询。其他平台的证书读取和系统验证在本项尚未实现，调用时明确报告 `unsupported_platform`，不能以此代表跨平台终态验收。9.6 的[TLS 配置与验证入口](tls.md)已接入；安全流在 11.3、跨库/随机源/模糊验证在 9.7 独立完成。

## 9.5 实施记录（2026-09-27）

Windows x64 的 `scripts/build.ps1 -Incremental` 构建通过，`txc.exe`、静态库、公开接口和包兼容清单一起生成。`scripts/check_x509.py` 临时生成 RSA 根/中间/叶证书和加密 PKCS#12，在 TX 中检查三层链、系统与自定义根、主机名、用途、过期/尚未生效、未知签发者、无效签名和非 CA 签发者；PEM/DER 畸形输入、65 张证书限额与错误密码按稳定错误码拒绝。导出的 PKCS#8 私钥由 Python `cryptography` 重新解析并核对公钥。原生定向用例重复验证和 PKCS#12 导入 20 次，系统句柄数未持续增长。测试用私钥仅在系统临时目录中短暂导出以验证互操作，随临时目录清理；终态模糊、跨平台、撤销查询和 9.7 总验收未运行。

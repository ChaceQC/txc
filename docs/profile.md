# 性能分析

Windows x64 和 Linux x64 提供 `profile.txh` 和 `txc profile`。报告只含源码位置、计数、大小和调用符号，不读取分配块内容、函数参数或配置值。

## API

`start(interval_ms = 10, max_allocations = 100000)` 启动进程级会话，间隔为 1～1000 毫秒，最多跟踪 1～1000000 个尚未释放的 C++ 分配。重复启动报 `profile_active`。`snapshot() -> str` 返回当前 JSON 报告；`stop() -> str` 停止采样并返回最终报告，重复停止返回已冻结报告。未启动时报 `profile_inactive`。再次启动清空旧会话。

`begin_span(name) -> int` 返回本会话唯一标识；`end_span(id) -> int` 记录并返回单调时钟经过的微秒数，可跨线程结束。空名、无效/重复结束、会话未启动或超过 10000 个段时报 `invalid_profile_span`。尚未结束的段在报告内保留 `duration_us=-1`。

## 采样和统计边界

Linux 用注册线程的 `pthread_getcpuclockid` / `clock_gettime` 取得 CPU 增量，通过 `process_vm_readv` 对 TX 诊断帧做两次一致性快照。不暂停应用线程，也不占用进程信号。帧切换、内存读取失败或访问限制时，把该次 CPU 时间保留为未归因样本并增加 `missed_samples`。Linux 不采集原生 PC，报告中的 `instruction_address` 为字符串 `"0"`，`sampler` 标记为 `thread_cpu_time_weighted_tx_frame`；源码归因仍是采样估计。下面关于暂停线程和原生 PC 的说明适用于 Windows 后端。两平台共用分配、存活堆、分段计时和报告格式；Linux 对齐分配使用 `posix_memalign`。

后台采样线程读取注册 TX 线程的系统 CPU 时间，短暂暂停线程取得原生 PC 和当前 TX 诊断帧后立即恢复。暂停区间不分配、不取得应用锁；只有恢复后才归并报告。CPU 时间增量加权归因到该次观察的位置，阻塞等待不作为 CPU 时间。返回前已退出的短命线程可能没有样本；1 毫秒参数不是精度承诺，实际调度间隔受 Windows 定时器和负载影响。`missed_samples` 记录读取失败或超过 100000 个位置上限。

导入 `profile.txh` 或使用 `txc profile` 时，编译器保留语句位置并标记标准库 C ABI 边界。报告区分 `tx`、`stdlib_abi`、无 TX 调用者的 `native`，原生库内部耗时归因到其 TX 调用点并保留 PC；不会把采样解释成精确逐函数调用计数。优化可能合并或删除纯计算，源码行是观测到的最近保留位置。

分配统计通过 C++ 全局 `new/delete`（包含数组及对齐分配）跟踪本会话开始后的分配，`heap` 按源码位置汇总仍存活块，不输出内存内容。开始前的分配、第三方 `malloc/realloc`、独立 DLL 分配器、系统句柄/GPU 内存不在范围内；它不是操作系统总内存快照。达到跟踪上限后增加 `dropped_allocations`，总分配次数/字节仍计数，存活快照成为下界。分析器自身的分配不计入。`sampler_us` 为采样器工作墙钟时间，不包括等待，也不代表全部开销。

## 命令行与可复现基准

```text
txc profile examples/profile_workload.tx --warmup 1 --samples 3 --interval-ms 10 -o tx_build/workload.profile.json
```

先编译普通与分析两个版本，再分别进行热身及正式运行；每次是独立进程和临时 cwd，程序不能依赖源码目录的相对夹具。程序会实际执行 `2 * (warmup + samples)` 次，外部网络/数据库等副作用不回滚。默认热身 1 次、样本 3 次，单次超时 30000 毫秒；失败/超时令命令返回 1 并写出已获得的结果，不把失败算成成功样本。

汇总记录 Windows x64、逻辑处理器数、`clang -O3`、热身数、样本数、采样间隔，以及普通/分析运行的墙钟毫秒和退出码。每个分析样本的 `profile_json` 是完整 JSON 字符串，读取时再解析，避免应用输出破坏汇总格式。普通与分析运行之差包含采样、分配跟踪、源码标记及进程调度开销；短任务可能为零样本，应延长真实工作负载。跨机器比较须另外记录硬件、系统版本和负载，不能用单个比值宣称固定开销。

## 本机验证记录（2026-09-30）

Windows 11 专业版 10.0.26200，AMD Ryzen 7 6800H，Release/`clang -O3`。`profile_workload.tx` 执行固定 200000 次文本构造及向量更新，热身 1 次、正式 3 次，采样参数 2 毫秒。完整报告可用上述命令重新生成，本次保存在 `tx_build/toolchain_profile.json`。

| 样本 | 普通版本 ms | 分析版本 ms | 有 CPU 时间的采样数 | C++ 分配次数 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 123 | 215 | 9 | 800014 |
| 2 | 121 | 210 | 11 | 800014 |
| 3 | 128 | 211 | 11 | 800014 |

中位数为 123→211 毫秒，本负载增加约 71.5%；不能把这个比例外推到其他程序。三个样本均记录 46416528 分配字节、0 个跟踪丢弃；采样器自身工作时间分别为 885/822/991 微秒，其余开销主要还包括分配跟踪及生成代码标记。系统 CPU 时间粒度和调度使采样数明显少于 `elapsed / 2ms`，因此报告同时提供真实样本数。本轮还通过了 API 启停、存活堆快照、分段计时和 TX 文件/函数/行归因的定向验证。

# class、接口与多态

预编译 Requests 类的字段槽位采用固定顺序（`requests.response`、`requests.session`），先于应用类分配，保证桥接库与应用使用相同布局。应用类的导入顺序不能改变这些标准库对象的字段编号。

`class` 是引用类型，赋值、传参和返回会共享同一对象；数组、字典和结构体也默认共享。`deep_copy(值)` 可显式复制包括类对象在内的可达对象图，保留共享关系和循环关系，不重新调用 `init`。类可以继承多个类或接口；共同祖先在同一个对象中只保留一份字段。继承列表按声明顺序查找构造方法，`super` 指向第一个直接继承的类。接口和抽象类可作为变量、参数、返回值及字段类型，但不能直接构造。

```tx
interface named {
    def label() -> str
}

abstract class animal : named {
    protected:
        name: str
    public:
        def init(name: str)
        {
            self.name = name
        }
        abstract def speak() -> str
        override def label() -> str
        {
            return self.name + ":" + self.speak()
        }
}

class dog : animal {
    public:
        override def speak() -> str
        {
            return "汪"
        }
}

def main() -> int {
    named pet = dog("豆豆")
    print(pet.label())
    dog actual = pet as dog
    print(actual.speak())
    return 0
}
```

## 声明与多继承

- 使用 `class 名称 : 父类一, 父类二, 接口名 { ... }` 声明多继承；`abstract class` 可有未实现方法；`interface 名称 : 父接口一, 父接口二 { ... }` 只包含公开的方法签名，不包含字段或方法体。类不能继承 `struct`，接口只能继承接口。继承环在编译期报错。
- 类体中的 `字段名: 类型` 声明字段；`def`、`virtual def`、`override def`、`abstract def` 声明方法。接口里的 `def` 隐式为公开抽象方法。类体默认 `private:`，可用独立一行的 `public:`、`protected:`、`private:` 切换后续成员的可见性。`private` 只允许声明类的方法访问，`protected` 允许声明类及其子类的方法访问，`public` 允许任何位置访问。
- 同一声明中的字段名不能重复。若不同父类有同名字段，直接通过子类类型访问会报歧义；可以先用 `as` 转成指定父类型再读取。共有祖先的同一个字段不算冲突。字段布局与访问权限在编译期确定，运行时不按字段名查找。
- 基本类型字段默认值分别为 `0`、`0.0`、`false`、空字符串、空数组、空字典。尚未赋值的 class、interface 或 struct 字段在读取时报运行时错误。`print(类对象)` 只输出类名和对象标记，不展开私有字段。

## 构造、析构与方法重载

- `类名(实参...)` 创建具体类实例，调用与实参匹配的 `init` 重载；若当前类没有 `init`，从父类按声明顺序查找。`init` 必须为 `public`、返回 `void`，且不能标记为 `virtual`、`override` 或 `abstract`。子类自己的 `init` 不会自动调用父类的 `init`，需要时显式调用 `super.init(...)`。没有 `init` 的类只接受空实参。
- `def deinit()` 是析构方法，不带参数、不返回值，不能重载、覆盖或手动调用。无环对象的最后一个引用释放时，从最派生类开始，按继承布局的逆序对各声明过 `deinit` 的类调用一次；共同祖先只调用一次。析构期间字段仍可读取。不可达的循环对象由[循环回收器](garbage_collection.md)在安全点回收；其中的类对象先执行一次 `deinit`，具体时机不保证立即发生。
- 同一类可定义多个同名方法，只要固定参数类型列表不同；返回类型和参数名不用于区分重载。继承来的其他签名仍参与选择。调用按静态实参类型匹配，优先选择总继承距离最短的唯一重载；无法唯一选择时报编译错误。命名实参和 `*args`、`**kwargs` 沿用普通函数的绑定规则。
- 方法内的 `self` 指向当前对象。`super` 指向声明列表中第一个直接继承的类；`super(父类名)` 可选择另一个具体父类或祖先类。`super.方法(...)` 与 `super(父类名).方法(...)` 直接调用所选父类实现，不做虚方法分派。`self` 和 `super` 不能作为参数或局部变量名。

## 运算符成员

类体可声明 `def operator +(other: 类型) -> 返回类型` 等运算符方法。左操作数是 `self`，因此方法可以按访问权限读取本类字段；`左值 + 右值` 只根据左值的静态类及其祖先选择方法。运算符可像普通方法一样使用 `virtual` 和 `override`；先在编译期确定签名，再按对象实际类执行虚调用。`super + 值` 直接调用所选父类实现。支持的符号、参数数量及返回类型限制见[语法说明](syntax.md#自定义运算符)。

## 接口、抽象方法与虚方法

- `virtual def` 提供可被覆盖的默认实现；`abstract def` 只声明签名且不写方法体，只能出现在抽象类中。接口方法也没有方法体。具体类必须为所有继承到的抽象签名提供实现，否则在类声明处报错。
- `override def` 必须覆盖继承来的虚方法或抽象方法。固定参数、可变参数、参数名和返回类型都必须与目标签名一致，访问权限不能降低。来自多个父类的相同签名可以由一个 `override` 同时实现；来自不同父类的同名同签名实现若未覆盖，在调用时报告歧义。
- 子类或实现类对象可隐式赋给任一父类或接口类型。通过这些类型调用虚方法时，根据对象的实际类分派到最终覆盖实现；普通方法的目标在编译期确定。方法重载选择也在编译期完成。

## 运行时类型转换

2026-09-29 的内部存储与静态方法入口见[静态对象布局契约](static_object_layout.md)。用户结构体和类使用只读类型描述及固定标量/引用槽，原生标准库拥有的记录保留其兼容表示；这些实现选择不改变下列转换与共享引用规则。

`引用 as 目标类或接口` 支持向上、向下及交叉转换。向上转换由编译器直接完成；向下和交叉转换检查对象的实际继承关系，成功时返回指向同一对象的引用，失败时报运行时类型错误。`any` 中装有类对象时也可用 `as` 转为类或接口。此语法不复制对象，也不允许把普通 `struct` 转成类。

类和接口可直接写在普通 `.tx` 文件中。通过 `.txh` 供其他模块导入时，`.txh` 写完整布局与方法签名，配对 `.tx` 重写同一声明并提供具体方法体；这与只在 `.txh` 定义一次的 `struct` 不同。文件对照、纯接口的例外和可运行示例见 [模块导入：`.txh` 与 `.tx` 的分工](modules.md)。

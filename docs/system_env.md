# 程序参数、环境变量与系统路径

`system.txh` 和 `env.txh` 面向当前 Windows x64 后端提供系统交互。公开接口位于 `tx/stdlib/`，实现随 `libtxstdlib.a` 交付。普通调用及重载均在编译期选定直接 C ABI。

## 程序参数与路径

导入 `import "system.txh" as system`：

| 接口 | 行为 |
| --- | --- |
| `args() -> vector<str>` | 返回传给生成程序的参数，不包含可执行文件名；无参数时返回空向量 |
| `current_directory() -> str` | 查询进程当前工作目录 |
| `set_current_directory(path: str) -> void` | 切换进程工作目录；相对路径基于切换前的工作目录解析，目标必须是已有目录 |
| `executable_path() -> str` | 查询正在运行的生成程序的完整路径 |
| `temp_directory() -> str` | 查询系统为当前进程选择的临时目录，不创建临时文件或子目录 |
| `home_directory() -> str` | 查询 Windows 当前用户配置文件目录 |

语言入口继续是 `def main() -> int`，不新增带参数的 main。生成程序在调用 TX main 前初始化参数：使用 Windows 宽字符命令行及 `CommandLineToArgvW` 的拆分规则，再严格转换为 UTF-8，因此中文、空参数、引号和带空格的参数不依赖活动代码页。参数属于运行的 `.exe`，与编译时传给 txc 的参数无关。参数不做选项解释或通配符展开。

每次 `args()` 返回独立的向量快照；修改向量不会改变原始参数或其他调用返回的向量。返回的字符串沿用不可变字符串语义。

系统路径统一返回 UTF-8 绝对路径，以正斜杠分隔，不承诺消解符号链接。可执行文件路径来自操作系统，不使用可能为相对路径的命令行首项推断。切换工作目录后，后续相对文件操作、`path.absolute` 和 `current_directory` 使用新目录；可执行文件路径和启动参数不变。工作目录属于整个进程。

临时目录选择遵循 Windows 的进程环境及系统规则，要求目录存在，但不保证可写；用户主目录通过 Windows 用户配置文件目录接口查询。所有系统查询和目录切换失败均沿用运行时中文错误及退出码 1。路径参数不能为空、含 NUL 或包含无效 UTF-8。

## 环境变量

导入 `import "env.txh" as env`：

| 接口 | 行为 |
| --- | --- |
| `contains(name: str) -> bool` | 判断变量是否已设置，已设置为空字符串也返回 true |
| `get(name: str) -> str` | 读取当前值，未设置时报告运行错误 |
| `get(name: str, default_value: str) -> str` | 读取当前值；仅在未设置时返回 default_value |
| `set(name: str, value: str) -> void` | 创建或覆盖当前进程的变量；空字符串保留变量，表示值为空 |
| `remove(name: str) -> bool` | 删除当前进程的变量；原本未设置返回 false，删除成功返回 true |

查询直接访问 Windows 进程环境，每次读取当前值。名称遵循 Windows 不区分大小写的规则，名称和值使用宽字符 API 严格转换 UTF-8。名称不得为空、包含 `=` 或 NUL；值不得包含 NUL。无效编码、名称及操作失败均报告运行错误。错误消息不回显环境变量的值。

`get` 的两个重载返回静态 `str`。缺失、合法空值和操作失败分别由默认值/严格查询错误、空字符串和运行错误表示，不将它们混成同一个 none。`default_value` 与其他实参一样正常求值，不是延迟回调。设置和删除只影响当前进程及此后继承其环境的子进程，不修改父进程或系统持久配置；接口不提供跨调用的原子事务。

## 示例

见 [system_env.tx](../examples/system_env.tx)：

```powershell
.\tx\txc.exe .\examples\system_env.tx
.\tx_build\system_env.exe "输入 文件.txt" --output "输出目录"
```

该示例只读取专用的 `TX_SYSTEM_ENV_EXAMPLE_LABEL` 变量，不枚举环境。设置、删除、空值及失败边界由本模块的定向验证覆盖。

## 实现与验证记录

2026-09-26：上述 11 个公开签名已接入 `.txh`、标准库 C++23 实现、直接 C ABI、LLVM 声明和调用；构建脚本会检查两个新增接口文件。`scripts/build.ps1` 构建通过，已更新 `tx/txc.exe`、`tx/libtxstdlib.a`，确认产物后清理了 `build/`。

按本次要求只执行少量验证，`python -X utf8 scripts/check_system_env.py` 的 7 个定向场景全部通过：

- 无参数示例：空参数向量及四种系统路径。
- 参数与进程状态：中文和补充平面字符、空参数、空格、引号和反斜杠，参数快照隔离；切换工作目录、相对路径及文件写入，可执行文件路径保持正确；继承的长环境变量、大小写规则、空值、覆盖、删除及默认值，命名参数和固定签名的展开调用。
- 四个运行错误：缺失变量的严格查询、非法变量名、值内含 NUL、切换到不存在的目录。
- 一个静态诊断：默认值类型不匹配，包含源码文件、行和列。

测试只向子进程传入专用测试变量，不打印其他环境变量，运行期间创建的测试目录退出时清理。未运行全量回归或性能测试。

编译驱动中 `_wspawnv` 拼接参数时丢失空格路径边界的问题已修复：内部启动 clang 和链接器时逐项添加双引号，并按 Windows 参数规则处理引号前及末尾的反斜杠。用户在 PowerShell 中也应以双引号包裹带空格的路径，命令示例见[编译与运行](usage.md)。

修复后重新构建并通过上述 7 个定向场景。脚本直接编译到中文带空格的目录和可执行文件名，同时使用中文带空格的编译临时目录，覆盖 clang 和链接器的参数传递；另外实际执行一次带双引号的 PowerShell 编译、运行命令，退出码为 0，带空格的程序参数及实际可执行路径均正确。

# 静态表示与生命周期体系改造

2026-09-30 根因报告的后续修复、定向验证及剩余边界见 [root_cause_repair.md](root_cause_repair.md)。

本轮以 `static_object_layout.md`、`static_borrowing.md` 的已有语义为基础，
将静态信息贯穿布局、调用和运行时执行。语言语法、类身份、别名、析构复活、
异常传播和标准库公开接口保持兼容。未知效果必须保守处理。

## 实施范围

1. 统一定型布局的槽位种类、引用边和原生表示选择；增加受检 AST 到 LLVM
   之间的分析层，缓存函数效果和调用决策，逐步接入现有优化。
2. 生命周期分析区分局部存储、调用期间借用、拥有结果和真正共享的对象。
   guard 优化必须覆盖正常退出、异常退出、重复关闭和逃逸回退。
3. 内部 ABI 保留稳定公共入口，静态字段和容器小操作尽可能直接发射。
4. 静态格式化生成直接操作并设置特化预算；动态格式化缓存绑定，固定 serde
   schema 的执行保留非法输入、重复字段及未知字段检查。
5. 结果计算与物化解耦；重复回调复用已解析签名、目标和上下文，错误边界仍逐次执行。
6. 定型追踪和复制复用布局；跨模块优化先验证工具链兼容性，再决定启用范围。
   TLS 后端和数据库连接策略不因单项倍率而替换。

## 正确性边界

- 栈上 record 只适用于已证明不逃逸的值语义结构体；类不能按值替换。
- 借用必须同时满足目标参数契约、后续实参求值稳定和所有者存活。
- 递归直接调用通过不动点摘要处理；间接调用、开放虚调用和未知外部效果保守处理。
- 缓存只保存元数据，不保存某次调用的值、字符串视图或句柄。
- 特化不改变实参求值顺序，也不能跳过未被模板引用的实参副作用。
- 无性能复测证据时，只记录消除的机制，不宣称倍率提升。

## 验证与交付记录

只执行受改动影响的定向检查与必要构建，不重复全量基准。
本轮已经接入以下执行路径：

| 方向 | 已实现 | 保守边界 |
|---|---|---|
| 布局与分析 | 共用槽位 ABI；全程序 SSA/CFG 与函数摘要；原生 record 支持标量局部、条件、循环、辅助函数及已证明的递归 | 256 字节原生存储预算；引用字段与未知动态调用回退；返回参数自身保留别名 |
| 生命周期 | int/float/bool mutex guard 使用调用者栈空间；共用正常及异常清理登记 | guard 只允许局部 get/set/close；wait、别名和逃逸继续使用拥有句柄；mutex owner 仍被持有 |
| 容器循环 | 已证明的标量辅助调用可复用向量稳定存储 | 同时要求无容器修改且 GC 中性；未证明的调用回退 |

| serde | 至多 32 个标量/文本字段生成 schema 读写函数及字段分派 | reject 策略的定型对象；未知字段、嵌套容器、大 schema 保持通用解析；读写检查不跳过 |
| 正则 | 不逃逸且只读取六个基础字段的局部结果写入调用者槽位，不构造捕获容器 | 读取 groups 等字段、修改或整体传递结果时完整物化；文本独立拥有 |
| 回调 | parameterized/property 循环复用目标、环境视图和当前线程 context | 各次回调仍独立设置/恢复错误传播；延迟绑定保留零次执行和缩减未执行时的行为 |

编译器与运行时内部元数据布局同步升级：`record_type` 为 144 字节，
`serde_schema` 为 120 字节；必须整包重建，不能混用旧标准库和新编译器。
槽位和局部 guard 的共用存储定义均纳入包 ABI 指纹。
生成的 C++ 回调桥带 `uwtable`，使底层异常能回到原 RAII 边界。

验证包括 `tests/static_execution.tx` 的正常/错误路径与 IR 检查，以及现有
format、serde、sync、regex、property、借用生命周期、GC 图与析构复活用例。
本轮不做全量性能复测，不将历史倍率作为新版本成绩。

## SSA、程序分析与 LTO

### SSA、程序分析与 LTO 实施约定

本次续接将受检程序统一降为函数级 CFG：表达式求值、局部绑定、字段/容器
读写、直接/间接调用、短路、分支、循环、返回和异常处理都必须有对应节点。
可失败操作的异常边在提交结果前分出；处理器及未捕获出口参与后续分析。
局部变量使用独立的绑定编号，遮蔽不共用状态；SSA 合流使用带前驱的 phi，
循环回边与异常合流均参与支配关系、活跃性和别名集合计算。

全程序分析覆盖本次编译加载的全部模块、函数及方法，以单调不动点传播
参数的修改、保存、返回别名以及对象引用边。递归互调必须收敛，未知外部
入口、间接调用和开放虚调用保留保守效果。外部资源和可复活类的存储不能
仅凭不逃逸摘要改为栈对象。分析层输出可检查的 CFG/SSA 与函数摘要。

移动推断仅作用于 CFG 证明所有后继路径均不再读取的拥有局部，并且使用
点确实转交拥有权。借用参数、特殊内联表示、异常处理器中的后续读取以及
循环下一轮的读取都禁止转移。原有清理根在转移时清空，结果立即进入清理
登记；不改变语言的显式 move 检查，也不提前触发用户析构。

LTO 使用与工具包 clang 同版本的 LLVM 链接器和 bitcode 标准库。C++ bitcode
仍以 x86_64-w64-windows-gnu 为目标，使用同一套 MinGW 头文件、libstdc++、
SEH 异常与线程运行库；第三方本机库保持本机目标。普通本机静态库继续
提供兼容链接路径。包指纹必须覆盖新增 bitcode 与链接工具，缺失或错配
不能静默退回普通链接并声称已执行 LTO。验证以语义、IR、异常生命周期、
递归/别名和实际跨模块优化证据为准，不重跑全量性能基准。

### 已接入的完整分析流程

`src/backend/analysis/` 为全部受检 AST 节点建立 CFG，包含短路求值、分支、
两类循环、字段/索引写入、解包、直接/间接调用、返回、异常分派和隐式清理。
拥有槽以空版本在入口登记，失败发生在初始化提交前时不会读取不存在的版本。
支配树与支配边界驱动带活跃性剪枝的 phi 放置，随后进行 SSA 重命名。
每次编译校验定义支配使用、phi 输入与前驱对应以及指令所属块的唯一性。

程序摘要覆盖本次编译加载的所有 TX 模块、函数和方法。别名采用按分配点的
保守集合，堆字段按对象合并；SSA phi、引用写入、参数间的包含关系、返回
别名及返回对象内部引用共同参与不动点传播。保存到调用者对象、传给未知
入口以及通过返回对象带出的值均计入逃逸。隐式清理会合并用户析构的调用
效果；没有重绑定的借用参数不按拥有参数析构。递归互调可以收敛，并支持
通过静态表示检查的原生 record 递归函数。

发射器实际使用这些结论：局部 record 的存储决策受逃逸结果约束，普通参数
借用使用统一的重绑定摘要，已证明的递归标量调用复用 GC 效果，拥有局部
在转交位置按所有正常及异常后继的活跃性推断移动。文本、bytes 和标量
容器可以省去最后一次使用时的句柄复制；有用户析构的值仅在安全返回转交
等保持生命周期的场景移动。分支后的读取、循环下一轮读取、处理器中的
读取、借用参数以及特殊局部表示会阻止移动。

`txc emit-analysis <源码.tx> [-o <输出.analysis.json>]` 可导出 CFG、SSA 输入、
支配关系、别名集合、参数修改/保存/返回摘要及移动候选。LLVM 发射继续
复用现有按领域划分的模块，生成的内存槽由 LLVM 优化提升为原生 SSA。
堆集合分析不宣称路径敏感、字段敏感或无限上下文敏感的精确证明；开放
动态行为依靠保守效果保留安全表示。

### 工具链与打包

构建生成 314 个 C++ 运行时/标准库 bitcode 模块和 3 个 TX 桥接模块，
与原来的第三方本机依赖归档成 `tx/libtxstdlib_lto.a`。clang、llvm-ar 和
ld.lld 使用兼容的 LLVM 23.1.2；C++ 头文件、运行库与 SEH 异常 ABI 延续
GCC 13.1.0 的 MinGW 工具链。普通 `libtxstdlib.a` 仍由 GCC 构建。
clang 的目标 CPU/指令集属性统一附加到全部 TX 函数及生成适配器，避免
ThinLTO 已导入函数却因目标属性不兼容而拒绝内联。

默认编译使用 ThinLTO：程序 IR 生成带摘要的 bitcode，由随包 ld.lld 与
bitcode 标准库共同优化和链接；`--no-lto` 显式选择本机库与 GNU ld。
`package.compat` 升级为 v3，额外校验 bitcode 库、clang 和 ld.lld 的 SHA-256。
不会在组件缺失或错配时静默改用普通链接。

引用字段内联、可复活类的栈存储、rw guard、map/queue 内部存储视图仍是
独立的表示优化工作。TLS 后端、SQLite 连接池策略和通用 GC 算法保持现状。
本轮只验证机制和语义，不新增性能倍率结论。

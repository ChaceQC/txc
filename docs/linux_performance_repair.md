# Linux 性能修复顺序

基线为 `benchmarks/linux_full_2026-10-01`。先处理 L/W 高差距，再处理 TX/C++ 高差距；历史 Windows 数值只用于选择热点，验收使用同机旧/新程序交替测量。

第一阶段：

- WebSocket 短帧头和正文合并发送，保持逐帧随机掩码、控制帧和长度校验。
- Linux 非递归目录名称枚举直接读取目录项，避免为仅需要名称的接口查询每项元数据；维持排序、中文路径和错误语义。递归/筛选接口保持原有行为。
- X.509 DER 重复解析只缓存最近一次成功验证的不可变 bytes 对象，使用弱引用，不延长其生命周期。内容不同、失效对象及无效证书仍完整解析；不缓存信任、用途、有效期或吊销验证结果。
- 日志逐条刷新语义不变。在 `/mnt/e` 与 Linux 本地目录分开测量日志、文件和启动，确认环境成本，不通过延迟写入掩盖错误。

第二阶段：检查 TX/C++ 的短文本序列化、队列、对象生命周期与循环扫描热点。只修改有明确根因且保持语义的路径，不把专用参考程序的语义差异视为必须消除的开销。

JSON/serde 解析热路径存在重复 peek：空白判断最多检查同一个字符四次，take 成功后 get 再次 peek，普通字符串结束分支也重复窥视。改为每步读取一次并共享消费/位置更新逻辑；保留流式跨块读取、UTF-8、转义、行列和字节限额错误。

原生流式验证同时发现既有 ASCII 批量输出会生成超过 4096 字节的单块。修正输出缓冲在 UTF-8 标量边界分块；纯内存序列化不走此路径。保留原断言，并增加断言行号以方便后续定位。

队列的 push/front/pop/back 热循环在原机器码中仍逐次调用 C ABI。针对这些小操作向 Clang 标注始终内联，使 ThinLTO 可在调用处合并容器解包；普通静态库保留导出函数，异常和空队列检查不删除。同轮复测从 1.276 ms 降至 0.877 ms，直接 ABI 调用从 3 处降为 0，保留此修改。

验证保留旧可执行文件，使用新目录构建候选；每组预热一次并交替采样五轮。补充相关错误边界验证，不重复全量测试。剩余差距、环境限制和未验证部分必须如实记录。

完整逐轮证据与未解决项见 [修复报告](../benchmarks/linux_repair_2026-10-01/README.md)。日志和文件在 `/mnt/e` 上的高倍率仍存在；没有取消逐条刷新。任务提交等待、通用对象生命周期及其他未修改路径不计作已修复。

CI/CD 使用 `scripts/check_runtime_hotspots.py` 在 Windows/Linux 验证 JSON、serde、类型化队列及异常清理，并在 Linux 验证目录枚举。结果写入 `tx_build/runtime_hotspot_checks/results.json` 并由 Actions 保存，失败会阻止工具包上传和 tag 发布。Linux 网络、证书、TLS、HTTP3 沿用原有独立步骤。共享 runner 不执行性能阈值判断。

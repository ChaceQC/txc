# 哈希键与排序契约

`map<K,V>`、`set<K>` 现可使用满足静态契约的用户结构体作为键。`K` 须有 `operator ==(other: K) -> bool` 和 `hash_key() -> int`；字段只能是不可变载荷的内置标量、`bytes` 或递归满足同一契约的结构体。`map` 的 V 暂仍限于 `int/float/bool/str`。普通类、可变容器和资源句柄不能作为键。编译器在容器类型出现的位置报告缺失签名或非法字段。

键在插入时深复制；`keys()`、`set.to_vector()` 也返回独立的键值。修改原结构体或快照中的结构体不影响容器内部的键。查询时只执行编译期绑定的哈希和相等方法；运行时不通过字符串方法名分派。用户方法执行失败会沿用原错误路径传播。`hash_key` 对相等键必须返回相同整数，这一函数体性质由作者保证，编译器只验证类型签名。哈希或相等方法应不依赖可变外部状态。哈希冲突由相等方法区分，平均查询复杂度为 O(1)，极端冲突为 O(n)。

浮点键继续拒绝 NaN，包括查询、插入和删除；`+0.0` 与 `-0.0` 是同一键且哈希一致。含浮点字段的用户键必须在自身的相等与哈希实现中保持相同规则。结构体键使用独立复制的字段值，`bytes` 本身是不可变载荷。

排序契约要求同类型 `operator <(other: K) -> bool` 或完整的 `fn(K,K)->int` 比较器签名；运算符调用和函数值绑定均在编译期选定目标并检查参数与返回值。比较器返回负、零、正，必须形成严格弱序；源码无法静态证明该数学性质。现有 `map/set` 仍是无序容器，`heap/queue` 仍限标量。有序容器使用比较器的公开构造、范围查询与回调存活期由计划 4.2、4.3 实施；本项只交付类型契约和已有函数值/运算符上的静态绑定。

用法见[结构体键示例](../examples/hash_keys.tx)，包括四种标量值、`set`、正负零、同类型 `<` 和 `fn(K,K)->int`。

## 2.3 实施记录

- **代码：** struct 增加 `hash_key` 成员声明；语义分析检查键的两个方法签名和递归值字段。`map/set` 的结构体键 ABI 使用编译期确定的直接回调，键插入及返回快照时深复制。现有标量键 ABI 保持原样，浮点 NaN 拒绝与有符号零一致性不变。
- **构建：** Windows x64 的 `scripts/build.ps1` 成功生成 `txc.exe`、标准库静态库与兼容清单。
- **定向验证：** `examples/hash_keys.tx` 编译运行，覆盖原键和快照修改、四种 map 值、set 重复键、同类型排序签名、正负零；`tests/stdlib/hash_module/main.tx` 跨 `.txh` 编译运行并输出 `7`。缺少方法与可变字段的两个源文件在使用位置报中文编译错误；`hash_key` 运行失败与 NaN 键分别报运行错误。未运行全量套件。
- **边界与验收：** 哈希一致性、严格弱序与回调不依赖外部状态仍是用户方法的语义约束；编译器不能证明任意函数体满足这些性质。有序容器、比较器在容器内的持有和自定义排序仍属 4.2～4.4；此处的排序契约已由现有运算符/函数值静态绑定验证。当前构建与执行证据限 Windows x64。

# 性能计划剩余回退修复

日期：2026-09-29。以当前 15～16 项工作树和已构建工具链为起点，保留其历史记录及未提交修改。公开语言、接口、错误信息、共享身份和数值精度不变。

## 已确认开销与方案

1. 局部解析的标量 ABI 在成功和解析失败时都查询 TLS，只用于取得待传播错误。新增显式 context 的内部入口，LLVM 使用已有 `%tx_context`；原入口继续可用。不得清空或遗漏上下文中已有错误。整数解析补上十进制专用扫描，保持所有进制的空白、符号、溢出后非法字符优先级。
2. map 的历史读入口存在 `any` 恢复和桶索引除法，没有 GC 安全点。对实际只有一个元素的 map，直接比较唯一键即可决定成功或缺失；其他大小保持原哈希查找。首版额外分支使 GCC 将多元素查找的一部分移出内联，128/8192 项实测回退，因此继续修正。数字键的 hash 本来不会抛错，却缺少 `noexcept`，使 libstdc++ 为每个节点缓存冗余哈希；补齐数字哈希和基础键比较的异常属性，保留文本哈希缓存以及 NaN 的入口检查，并让 singleton 返回原生迭代器，简化后续查找合流。此异常属性会改变原生节点布局，相关头文件纳入 ABI 指纹并整体重建，不混用旧对象。该路径不缓存元素地址，不改变遍历顺序、共享别名或 rehash 行为。历史约 0.4 ms 差值的硬件原因尚未证实，不能把以上结构开销直接说成历史回退根因。
3. UTF-8 编解码逐码点校验，解码后的 `len` 又执行类似扫描。以相邻四字节的合法性关系批量验证和计数，允许普通 Release 编译器自动向量化；短文本保留直接扫描。拒绝孤立续字节、截断、过长编码、代理项和超出 U+10FFFF 的编码，不越界读取。字符串长度仍按 Unicode 标量计数，保留各调用方原有错误类别和消息。str/bytes 仍各自拥有内容，不更换共享表示。
4. 中断恢复发现重复增量构建会再次合并已包含第三方对象的发布静态库。CMake 的未合并静态库改放临时 build，每次打包先复制该库，再加入 TX 桥接对象和依赖，避免发布库从约 32 MB 重复增长到 44 MB；最终完整包仍放 tx。

第二轮复核确认 GCC 仍将多元素 `find` 移出内联，因此仅为四个基础 map ABI 源文件提高 GCC 内联预算，不对整个项目或第三方库改优化选项。UTF-8 首版把短路径与批量核放在同一函数，Windows 调用约定导致短路径也保存大量 SIMD 寄存器；批量核改为独立编译单元，ASCII 前缀采用安全的字宽扫描，保留长文本收益并修复短 hex 长度计算的新增开销。

编码校验及字符串长度对不足 32 字节的文本保留原本可内联的逐码点循环，避免短输入支付公共扫描入口成本；计数最多 31，局部计数无需逐项检查 int64 溢出。长输入继续保留最终计数范围检查。

## 验收边界

- 修改前冻结完整包、DLL 和原负载；修改后同轮交替测量 map、解析局部/完整结果及 UTF-8 短/长负载，逐轮核对校验值。
- 定向检查所有整数进制和错误优先级、显式上下文的既有错误、map 的空/单/多元素转换及别名、UTF-8 所有码点和无效边界、长度和 BOM 语义。
- 重建编译器、静态库及三个 TX 桥接对象，核对 ABI 指纹和包兼容性；成功后清理临时 build 目录。
- LTO 保持计划 16 的条件性决定。当前普通工具链可修复的热点先按本方案处理；没有端到端收益证据时不迁移全部第三方库及链接器。
- 独立完整契约 C++ 对照、所有类析构/资源覆盖等原报告限制仍逐项保留，不能把本轮定向修复称为整个语言的性能达标。

# 优化 12–14 的内部契约

2026-09-29。实施起点：`85433b3`，工作树干净。公开语言规则与接口保持不变。

- 迭代器复用局部标量 option。仅对整个函数中不逃逸、不重绑定的局部标量 snapshot 缓存稳定游标视图；视图由原句柄保活。next 在读取成功时立即推进共享 index，在首次读空时立即标记永久耗尽；close 后先报告原 invalid_state，再考虑耗尽。实时、别名和复合迭代器继续使用原入口。闭包或其他调用无法取得已证明不逃逸的游标，仍有逐次 closed 检查供不能提升检查的路径使用。
- 整数除法先排除零以及最小整数与 -1，再执行 LLVM 原生指令；取余沿用原先的安全常量路径，最小整数 `% -1` 仍返回 0。浮点除法仅检查正负零，不改变 NaN、无穷或舍入行为。错误分支调用原算术入口。加减乘的值域证明仅利用常量、不改写的局部变量、循环上下界及局部条件；证明不足继续使用 overflow intrinsic。诊断位置只在同一基本块内去重，保留逻辑帧及错误位置。
- 字面量数组和字符串键字典展开在编译时绑定，但按源码顺序执行每个值表达式。只有参数类型、重复键、缺失/多余参数均可证明合法时才启用。可变参数仍创建独立浅复制容器；错误或动态形状继续使用运行时绑定及其原错误时机。已知目标不重新进行函数名分派，动态绑定直接读取已绑定的参数槽。
- 固定字段按第 09 项描述复制；标量直接复制槽，已知 str/bytes 引用复制值，动态对象边才递归。所有可共享对象仍先登记副本再填充。扫描继续使用描述中的对象边索引；局部 owner 扫描在登记锁内筛选弱引用，工作图只在单次回收中持有强引用。不可达类先析构、再完整重判可达性，清理继续保留最初错误。

定向验收与同轮样本记录在 `benchmarks/performance_optimization_12_14_2026-09-29/`。性能变化与结构/行为通过分别报告；小向量以 int64、1k/100k 两种尺度对照，不移除没有证明的求和溢出检查。

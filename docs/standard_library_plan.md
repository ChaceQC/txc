# 标准库终态实施顺序

本文是[标准库终态设计](standard_library_complete_design.md)的**实施清单**，替代原有的“标准库扩展规划”全文。原文中的早期批次、过时缺口和分散的实施记录不再作为待办或范围依据。本文按依赖关系列出小工作项；编号表示依赖顺序，不代表版本、可选范围或必须等所有较小编号完成才能推进无依赖工作。十类能力均达到终态设计的[验收矩阵](standard_library_complete_design.md#14-终态验收矩阵)，计划才算完成。

截至 2026-09-26，当前仓库已经有基础容器与算法、`string/encoding/bytes`、文件与系统接口、时间与随机数、JSON、HTTP/WS/Requests 以及一组密码学接口。这些是扩展的起点，不重新作为“待实现”排队；每项开始时仍须核对公开 `.txh`、源码和现有文档，确认实际缺口。第 1 节的公共契约与兼容校验、2.1～2.5、2.7～2.8 及第 3 节已落地；2.6 与第 4 节及之后的新增能力仍为规划，不能视为已经验收。

## 执行规则

1. 每个编号小项先固定具体接口、类型和失败语义；涉及语言规则时先更新[语法说明](syntax.md)与示例，再动编译器。随后交付 `.txh`、对应层的实现、C ABI/LLVM 调用、模块文档和必要的定向验证。
2. 复用现有模块与静态库，不因引入新 API 改变旧函数的排序、编码、错误或共享语义。新旧能力并存时写出迁移示例。
3. 不把“接口已声明”“构建通过”“本机一次往返”单独记为完成。完成记录至少区分代码、构建、定向验证、外部依赖/平台边界和终态验收。
4. 验证按变更直接影响的正常路径、失败路径和资源清理选取；解析器、网络、并发、数据库与密码学的最终专项验证放在相应小项和总验收中，不重复跑与改动无关的大套件。

## 1. 盘点与公共契约

- [x] **1.1** 对照 `tx/stdlib/*.txh`、`src/stdlib/` 和已有模块文档，建立“终态能力 → 已有接口 → 缺失接口 → 验收证据”清单；已实现但未专项验证的边界单独标记。

- [x] **1.2** 固定公开模块名、类型名、命名规则与跨模块依赖。决定旧接口保留方式、泛型设计记法到真实 `.txh` 的落地方式，以及不能兼容时的新接口名称。

- [x] **1.3** 建立统一错误码登记：保留 `parse_error/io_error/runtime_error`，定义 `process_error/database_error/security_error/cancelled_error` 与各模块的稳定 `code`，明确严格接口和结果接口何时使用。

- [x] **1.4** 固定资源句柄状态表：创建、借用、共享、关闭、重复关闭、失败后可用性、作用域清理和部分外部效果。文件、socket、进程、线程、游标等统一遵循这套规则。

- [x] **1.5** 为 `txc`、`.txh`、标准库静态库和运行时 ABI 建立兼容指纹；混用不匹配产物时给出诊断。固定新增第三方依赖的版本、校验值、许可证与发行方式。

**完成判定：** 后续每个模块能引用同一套错误、资源、ABI 和兼容规则；清单不再把已实现的基础能力误列为缺口。

本节的逐类盘点、公共契约、依赖登记和代码/验证记录见[标准库公共契约与现状清单](standard_library_foundation.md)。

## 2. 类型系统、回调与运行时基础

- [x] **2.1** 扩展内置参数化类型实例化机制，让 `vector<T>` 等类型可存放用户结构体和嵌套容器；先处理静态类型、布局、引用所有权、循环回收、`deep_copy` 与 `any` 显式恢复。

- [x] **2.2** 实现 `option<T>`、`result<T>` 和 `result<void>`。明确无值与错误的表示、模式检查、错误传播；给现有具体 `error.*_result` 保留兼容接口与转换桥。

- [x] **2.3** 实现编译期哈希、相等和排序契约：用户键类型的 `operator==/hash_key`、有序比较器、浮点 NaN/有符号零和键不可变性。静态不满足契约时在源码位置报中文错误。

- [x] **2.4** 实现 `iterator<T>` 与快照/实时遍历区分；保留现有 `vector` 遍历行为。迭代器失效、容器中途修改和回调错误的行为写入语言文档。

- [x] **2.5** 将现有无捕获顶层 `fn` 扩展为类型明确的闭包。定义值捕获、受控借用、回调存活期、错误传播与捕获形成引用环时的回收。

- [ ] **2.6** 增加 `Send/Sync` 的静态规则与唯一移动/同步共享边界。普通可变容器别名不能直接并发写；不透明句柄逐类声明可否跨线程。分为两个阶段，均通过后才勾选 2.6：

  - [ ] **2.6a 静态规则与运行时基础：** 固定各类型及闭包捕获的 `Send/Sync` 判定，建立可检查的唯一移动与别名边界；处理句柄跨线程转移、引用计数、释放和循环回收安全点。不透明句柄默认禁止，逐类证明后放行。用源码位置诊断及运行时定向验证确认基础规则，不把断言通过当作线程集成验收。
  - [ ] **2.6b 最小线程/锁入口的集成验收：** 在 2.6a 基础上，接入 10.1 的最小 `thread.spawn/join` 与 10.2 的最小 `mutex<T>` 受控访问入口，验证 TX 代码中的唯一移动、普通别名拒绝、锁外访问拒绝、闭包捕获、错误传播、跨线程释放和循环回收。最小入口通过只完成 2.6 的验收所需部分；10.1/10.2 的完整接口及各自验收仍按第 10 节推进。

  具体规则、现状及两阶段完成条件见[Send/Sync 与跨线程所有权边界](send_sync.md)。2.6 未完成时可推进第 3～9 节中不依赖跨线程的工作；除 2.6b 所需的最小 10.1/10.2 入口外，依赖共享 TX 值或并发运行时的后续工作须等 2.6b 通过，不能提前标为已验收。

- [x] **2.7** 扩展运行时调用栈与源码位置映射、异常类别匹配和清理路径。新增 `option/result`、闭包和资源句柄均须在正常返回、异常与循环回收时释放正确。

- [x] **2.8** 定义跨模块的取消令牌与截止时间：取消如何唤醒阻塞操作、完成与取消同时发生时的结果，以及已产生的外部效果如何报告。

**完成判定：** 代表性用户结构体、嵌套容器、闭包与新结果类型可跨模块编译调用；无效类型、非法跨线程共享和资源误用能静态或运行时明确报错。

## 4. 集合、排序与组合算法

4.1 在现有 `vector` 上扩展复合元素的构造、增删、索引、遍历与独立复制；加入双端 `deque<T>` 并固定复杂度。

4.2 扩展 `map/set` 的键和值类型，新增成对 `entries()` 快照；实现 `ordered_map/ordered_set` 的比较器、范围查询与遍历顺序。

4.3 扩展 `heap/queue` 的复合载荷、批量构建和稳定优先级条目；空容器、NaN、比较器修改状态等失败语义固定。

4.4 在 `algorithm` 增加稳定排序、二分范围、去重、旋转、分区与自定义比较器；区分原地与返回新容器的调用。

4.5 增加 `map/filter/fold/all/any` 等类型化组合算法，确保回调签名在编译期选定，静态已知元素不逐项装入 `any`。

4.6 验证共享引用、`deep_copy`、`any` 恢复、迭代中修改、比较器出错、整数溢出及结构体析构。

**完成判定：** 终态设计中的列表、哈希/有序集合、队列、堆和排序场景可以用静态类型直接实现。

## 5. Unicode、正则与增量编码

5.1 固定随工具链交付的 Unicode/ICU 数据版本，提供 NFC/NFD/NFKC/NFKD、完整大小写与 case fold；保留旧 `string.lower/upper` 的 ASCII 行为。

5.2 实现 Unicode 标量遍历、字素簇切分与计数、字符类别、显示宽度和显式 locale 比较器；标清所有索引单位。

5.3 用 PCRE2 实现 `regex` 的编译、捕获、匹配、查找、替换与拆分；定义 Unicode 模式、零长度匹配推进和可定位的语法错误。

5.4 给正则执行设置输入大小、步数、深度与取消限制；不可信模式超限时返回稳定错误而非无界占用。

5.5 扩展 `encoding` 的 UTF-32 和增量编码器/解码器；跨块保存部分字符，仅在 EOF 仍残缺时失败。非法字符替换必须显式选择并能计数。

5.6 扩展 `bytes` 的 URL 安全 Base64 与有界分块编码；核对 `str` 和 `bytes` 不发生隐式混用。

**完成判定：** 多语言文本、正则与跨块编码的正常及无效输入场景均有明确位置、限额和可复现结果。

## 6. 时间、数学、随机数与统计

6.1 在旧 `time.unix_millis/monotonic_*` 之外建立 `duration/instant`；固定溢出、负值、睡眠取消及单调时间与墙上时间的转换边界。

6.2 增加日期、时刻、带偏移/带时区时间，交付固定版本的 IANA 时区数据；解析和格式化 ISO 8601，显式处理夏令时缺失/重复时刻。

6.3 在旧全局 `random` 接口之外提供独立可设种子的生成器、抽样、洗牌和分布；算法版本、状态所有权及跨线程规则明确。

6.4 扩展 `math` 的三角、指数、对数、`gcd/lcm`、舍入与有限值判断，逐函数规定定义域、NaN、无穷大与整数溢出。

6.5 实现 `statistics` 的均值、中位数、方差、标准差、分位数及流式累计器；区分样本/总体公式和空样本。

6.6 实现 `decimal` 的文本构造、精度、舍入和四则运算；禁止从二进制浮点隐式构造金额。

**完成判定：** 时区歧义、可复现模拟、统计边界和十进制金额计算有完整示例与定向证据。

## 7. 文件系统、环境与子进程

7.1 扩展 `fs` 的 `stat/lstat`、权限、时间戳、符号链接、目录筛选和文件监视；区分跟随链接与观察链接本身。

7.2 扩展 `path` 的真实路径解析、根/文件名/扩展名分解和平台比较规则；保留词法 `normalize/absolute/relative`，不把路径字符串规范化当作安全边界。

7.3 给 `file/file_stream` 增加整文件二进制便捷接口、原子替换、显式持久化与协作式文件锁；注明跨卷、断电与部分写入限制。

7.4 扩展 `system/env` 的系统/架构/CPU/进程信息、环境快照和能力查询；当前工作目录、环境修改的进程全局影响须写清。

7.5 实现 `process` 的不经 shell 启动、参数转义、工作目录、环境覆盖、`wait/try_wait/terminate/kill` 与退出状态。

7.6 接通 stdin/stdout/stderr 管道与有界 `run` 捕获；同时消费两路输出，不因管道缓冲造成内部死锁。超时不隐式杀进程，策略由选项明确。

7.7 验证中文/空格路径、权限、符号链接竞争、短读短写、进程超时、子进程结束后句柄清理和文件监视溢出。

**完成判定：** 大文件处理、原子保存、目录监视和安全传参启动进程均有公开、可恢复失败的完成路径。

## 8. JSON、CSV、XML、CBOR 与结构化映射

8.1 为已有 `json` 增加增量读取/生成和可选 schema 校验；保留现有 `any/array/dict` 与严格解析规则。

8.2 实现 `csv` 的流式读写、表头和 dialect；覆盖引号内换行、空字段、BOM、字段长度与行宽上限。

8.3 实现 `xml` 的拉取式 reader、树和 writer；固定命名空间语义，默认禁用 DTD、外部实体、网络实体与 XInclude。

8.4 实现规范化 `cbor` 编解码与分块流；明确重复键、无效编码、深度和长度限制。

8.5 为 TX 数据结构定义编译期字段元数据和 `serde` 生成规则；处理字段编号、默认值、未知字段、schema 版本与显式迁移。

8.6 验证解析位置、缺字段/类型不符、循环引用、流式半写入、不可信输入限额及跨版本往返。

**完成判定：** JSON、CSV、XML、CBOR 可处理大数据；结构体序列化有固定 schema，不能序列化原生句柄或私钥。

## 9. 密码学、密码与证书

9.1 在现有 `crypto` 和 `bytes` 之外实现不可打印的 `secret_bytes`；规定导入/导出、清零、别名、`any`/序列化禁用及平台内存限制。

9.2 实现 Argon2id 的密码哈希、验证与参数升级；使用独立随机 salt、PHC 字符串、安全参数边界。

9.3 扩展流式 SHA-2/HMAC 与有版本、块序号和最终块认证的大文件加解密；整体认证完成前仅写受控临时文件。

9.4 实现 Ed25519 签名/验签、X25519 密钥交换及标准编码；私钥使用不透明句柄，交换结果经 HKDF 派生。

9.5 实现 X.509 PEM/DER/PKCS#12 读取、证书链、主机名/用途/有效期和系统/自定义信任锚验证；撤销未检查时给出明确状态。

9.6 定义 TLS 证书、信任锚与客户端身份配置及验证入口；默认启用验证，不默默接受无效证书。具体 socket/TLS 接入在 11.3 完成。

9.7 用公开标准向量、跨库互操作、错误密钥/标签/证书、随机源失败和资源清理证据完成验收。

**完成判定：** 密码存储、签名、证书与大文件认证加密均可安全组合；旧 `TXCG` 单段格式保持兼容。

## 10. 线程、任务与进程间通信

10.1 实现 `thread.spawn/join/detach`，接入 `Send/Sync`、错误回收、线程退出与循环回收安全点。

10.2 实现 `mutex/rw_lock/condition/semaphore/once/atomic`；锁卫士按作用域释放，原子内存序与持锁跨等待规则明确。

10.3 实现有界 `channel<T>`、关闭/EOF、背压、`select`、超时与取消；不得丢失已交付消息。

10.4 实现结构化 `task.scope`、任务组、取消、截止时间与 `task<T>`；作用域结束不得留下未知后台任务。

10.5 在语言与运行时接入 `async`/`await`、有界工作线程及 Windows IOCP 事件循环；同步旧接口继续可用，异步 I/O 不靠无限开线程模拟。

10.6 实现可取消 I/O 的通用桥接和文件异步操作；规定取消后如何报告已完成的外部效果与句柄状态。socket/HTTP、数据库的具体适配分别在 11、12 节完成。

10.7 实现本机 IPC 消息流、子进程管道与基于 CBOR 的版本化消息；区分 EOF、半包、重启与消息超限。

10.8 验证数据竞争静态拒绝、关闭/取消竞态、任务失败传播、GC/析构及长时间运行的句柄上限。

**完成判定：** 多任务网络服务、有限队列消费与进程间通信在类型和资源规则内运行。

## 11. 低层网络、TLS 与协议客户端/服务端

11.1 实现 `dns` 的地址解析、TTL、超时、取消与错误分类；解析失败不返回普通空列表。

11.2 实现 `socket` 的 TCP/UDP、监听、半关闭、短读短写、报文边界与有界缓冲；同步和异步接口共用状态规则。

11.3 实现 `tls` 的客户端/服务端安全流、系统或自定义 CA、主机名验证、客户端证书、ALPN 与关闭行为。

11.4 扩展 `httpx` 的连接池、可重用会话、真正的流式请求/响应、压缩和代理；保留既有显式 HTTP/2 函数语义。

11.5 扩展 HTTP 服务端的路由、并发连接/流、背压与处理函数上下文；完成 HTTP/1.1 与 HTTP/2 的并行流、非法帧及限额专项验证。

11.6 增加 HTTP/3/QUIC 与显式协议协商或降级策略；握手、0-RTT、取消、迁移与流限额写入独立协议文档。

11.7 扩展 `websocket` 的 TLS 服务端、共享 HTTP 监听器的 Upgrade、ping/pong 与异步收发；关闭原因与合法空消息区分。

11.8 完成 `requests` 的底层连接复用、`stream=true`、显式代理、自定义 CA/客户端证书、Cookie 处理和安全重试；旧 `unsupported_option` 不得被静默忽略。

11.9 验证证书错误、慢连接、重定向凭据保护、压缩比/正文上限、非法请求/帧、取消后句柄状态及大文件流。

**完成判定：** HTTP/1.1/2/3、WS、TCP/UDP 与 TLS 的客户端/服务端场景均能按终态设计完成。

## 12. 数据库、事务与迁移

12.1 定义 `db` 的连接、语句、参数、执行结果、游标、行与事务类型；NULL、无行、列缺失和类型不符分别表示。

12.2 集成 SQLite：路径、只读/WAL、忙等待、参数绑定、逐行读取和事务回滚；固定线程模式与连接并发限制。

12.3 集成 PostgreSQL：libpq、TLS 与主机名验证、SQLSTATE 映射、参数绑定、服务器断连与失败事务状态。

12.4 实现有界连接池、获取超时与归还时清理；一个连接上的活动游标和事务规则明确。

12.5 实现 schema 迁移的版本号、校验值、互斥和各驱动支持的事务边界；失败后可确定已应用到哪一步。

12.6 接入任务运行时的异步查询与取消，明确请求已发送、事务已提交等不可撤销边界。

12.7 验证参数化查询、约束冲突、NULL/无行、保存点、断连、池耗尽、失败事务与关闭后误用。

**完成判定：** 本地数据库和客户端/服务端数据库都能安全查询、流式读取与管理事务。

## 13. 工具链补齐与终态总验收

13.1 完成 `test` 的参数化/性质测试、失败种子和反例缩减，补齐测试隔离、并行、超时及报告格式。

13.2 完成 `log` 的轮转文件、任务/线程/请求上下文与并发写入保证；核对所有模块的秘密字段遮蔽。

13.3 完成 `profile.txh`、`txc profile` 的 CPU 采样、分配/堆快照和源码级归因；记录开销、热身与样本环境。

13.4 核对所有模块的 `.txh`、静态库符号、依赖许可证、ABI 指纹、中文文档和可运行示例；安装后的示例不能依赖源码树中的私有文件。

13.5 分别完成十类能力的[终态验收矩阵](standard_library_complete_design.md#14-终态验收矩阵)，并跑通“文件 → 数据格式 → 数据库”“网络 → 并发 → 数据库 → 日志”“密码 → 证书 → TLS/安全存储”三条跨模块链。

13.6 汇总静态诊断、外部失败、部分效果、资源释放、取消竞态、模糊测试、标准向量与互操作证据；明确 Windows x64 发行物的完整支持状态，其他平台按同一契约分别验收。

**完成判定：** 十类能力均满足终态设计，发行物可复现构建、可运行示例、可核查错误与资源边界；没有仍被当作“以后再补”的清单项。

# TX 标准库终态设计

本文定义 TX 对常用通用程序提供的**完整标准库目标**，覆盖集合与数据结构、字符串与编码、文件与系统、时间与数学、网络、数据格式、并发、数据库、测试与调试、安全十类能力。这里的“终态”指以下能力、语义和验收条件全部交付后的状态，不表示当前代码已经支持本文列出的新增接口，也不以某个先行版本代替最终目标。

本文以 2026-09-26 仓库中的 `tx/stdlib/*.txh`、`src/stdlib/`、`CMakeLists.txt` 和现有语言文档为静态核对依据；未在本次文档工作中构建或运行程序。已经公开的行为以现有模块文档为准；本文中标明“新增”或“扩展”的签名是**拟定终态契约**，落地前须同步 `docs/syntax.md`、模块文档和可运行示例。泛型签名里的 `T`、`K`、`V` 是设计记法；其中 `algorithm` 和 `serde` 已落地为受限的标准库泛型接口声明，普通用户泛型函数体仍不支持。

## 1. 完成边界与现状

终态面向通用命令行工具、长期运行的网络服务、数据处理程序和安全敏感应用。正式支持矩阵至少覆盖仓库当前的 Windows x64 工具链；跨平台核心使用相同的 TX 行为契约，增加其他目标平台时须提供对应适配器和同一套验收。标准库不承诺实现每一种第三方协议、科学计算框架或数据库驱动，但下表列出的日常任务必须有公开、类型明确、可恢复失败的完成路径。

“已有”表示能在当前接口及对应源码中找到实现入口，不等于本次重新验证。“缺口”包含没有公开模块，以及已有模块中已在专门文档明确写出的限制。

| 类别 | 当前可复用能力 | 距终态的主要缺口 |
| --- | --- | --- |
| 集合与数据结构 | 异构 `array/dict`；类型化 `vector/deque/map/set/ordered_map/ordered_set/heap/queue`；`algorithm` 的排序、查找、统计与组合算法 | 第 13 节的全库、发行物和跨平台终态验收 |
| 字符串与编码 | UTF-8 `str`、基础子串处理、格式化、`bytes`、UTF-8/UTF-16/GBK/GB18030 转换 | Unicode 规范化、完整大小写映射和字素簇、正则表达式、增量编码器 |
| 文件与系统 | `file/file_stream/fs/path/system/env`；文本和二进制流、常用路径与环境操作 | 子进程、管道、原子替换、权限/符号链接/元信息、文件监视、系统能力查询 |
| 时间与数学 | 时间戳、单调计时、休眠、伪随机数和基础数学 | 日历/时区、可控随机数实例、统计、高级数学、十进制定点数 |
| 网络 | `httpx`、`websocket` 和 `requests` 的同步 HTTP/WS 能力，含 HTTP/2 与文件流 | TCP/UDP/DNS/TLS 低层公开接口、异步 I/O、连接池、代理/自定义信任、完善流式会话与服务端并发 |
| 数据格式 | 严格 JSON 解析、序列化、字段读取、增量数组与受限 schema；CSV 流式读写、表头与 dialect；XML reader、树、writer 与安全默认值；CBOR 确定性编解码与根数组流；`serde` 固定 schema 的 JSON/CBOR 结构体映射和显式版本迁移 | 第 8.6/13 节跨格式、大数据和跨平台专项验收 |
| 并发 | 当前仅有无捕获的顶层函数值；网络服务循环同步执行 | 线程、任务、取消、同步原语、通道、异步文件/网络 I/O、进程间通信 |
| 数据库 | 无公开数据库模块 | SQLite 与 PostgreSQL 连接、参数绑定、游标、事务、连接池和迁移接口 |
| 测试与调试 | `test/log/debug` 与 `txc test` 已有第 3 节基础接口；仓库另有针对编译器/标准库的脚本和样例 | 参数化/性质测试、并行与超时、可替换日志 sink/轮转、性能分析及终态验收 |
| 安全 | `crypto` 已有安全随机数、SHA-2、HMAC、HKDF/PBKDF2、AES-256-GCM；HTTP 客户端验证 TLS | Argon2id、非对称签名/密钥交换、X.509 与证书存储、可控密钥生命周期、大文件认证加密 |

当前 `vector<T>` 已支持基础值、用户结构体和嵌套容器；4.1 新增的 `deque<T>` 已支持同类具体元素与双端操作。`map/set` 的哈希键支持满足编译期契约的结构体；4.2 将 `map` 值扩展为具体复合类型并提供 `entries()` 快照，新增 `ordered_map/ordered_set` 的比较器、范围查询与有序遍历。4.3 将 `heap/queue` 扩展为具体复合载荷、批量构建和稳定优先级条目。4.4～4.5 新增静态泛型算法接口，4.6 的集合交叉边界已定向验证。`requests` 的 `stream=true`、显式代理、自定义 CA/客户端证书和底层连接池尚未实现。网络的 HTTP/2 并行流等边界也尚无专项验证。具体工作项与依赖顺序见[标准库终态实施顺序](standard_library_plan.md)。

## 2. 全库统一契约

### 2.1 模块、类型和编译边界

- 公开 API 只放在 `tx/stdlib/*.txh`。纯 TX 包装源码可在 `src/stdlib/*.tx`，原生实现放在 `src/stdlib/`，ABI 桥接放在 `src/backend/cpp/`；最终归档到 `tx/libtxstdlib.a`。驱动只负责编排，不承载库逻辑。
- 静态已知的重载、参数类型、回调签名和容器元素操作由语义分析与代码生成确定。协议协商、输入内容、系统状态、网络响应、数据库列值等真正动态的数据在运行时检查。对新增模块不得以字符串函数名分派或逐元素 `any` 装箱掩盖缺失的类型实现。
- 终态扩展内置参数化类型，使 `vector<T>`、`deque<T>`、`option<T>`、`result<T>`、`task<T>`、`channel<T>` 可承载任意符合生命周期规则的具体类型；`map<K,V>`、`set<K>` 对键类型要求编译期可验证的哈希与相等契约。编译器为实际使用的具体类型实例化实现，不要求先引入用户可定义模板语法。`array/dict/any` 继续承担 JSON、数据库行等确有动态形状的边界。
- `option<T>` 明确表示“存在或不存在”；`result<T>` 包含成功值或 `error.error_info`，不能用 `none`、空字符串、0 或 EOF 表示失败。现有 `error.int_result/float_result/str_result/bool_result/any_result` 和已公开函数保持兼容；新增结果 API 使用统一的 `result<T>`，需要时提供无损转换桥。
- `result<void>` 表示只需要确认成功与否的操作。用户结构体作为哈希键时须提供编译期可识别的 `operator==` 与 `hash_key() -> int`；作为有序键时须提供 `operator<` 或显式比较器。`hash_key` 必须与相等规则一致，键在容器内不可修改。这些静态契约需要先写入语言文档。
- 回调终态支持类型已知的闭包与捕获。同步调用可借用受控数据；跨线程或异步存活的闭包必须持有其捕获值，并由编译器检查“可跨线程传递/共享”约束。现有顶层 `fn` 仍可用。捕获对象的析构、循环引用和异常传播必须遵守现有所有权规则。
- 扩展 `iterator<T>` 与流式游标时，要规定迭代期间修改容器的行为。现有 `vector` 遍历“记录初始长度、逐次读取当前值”的语义不变；新增快照遍历与实时迭代采用不同 API，不能悄悄改变旧代码结果。

### 2.2 错误、资源和可观察行为

| 事项 | 终态规则 |
| --- | --- |
| 错误分类 | 保留 `parse_error`、`io_error`、`runtime_error`；增加可捕获的 `process_error`、`database_error`、`security_error`、`cancelled_error`。每个错误均有稳定的 `kind/code` 和用于阅读的中文 `message`；程序分支依赖 `code`。 |
| 返回与抛错 | 预期分支如缺键、EOF、无匹配、查询无行使用 `option<T>` 或显式状态。失败操作提供严格接口与必要的 `try_*`/`result<T>` 接口；两者使用相同错误码。分配故障和损坏的不变量仍可抛错。 |
| 错误位置 | 编译诊断保留源码位置；运行时错误保留原始错误和可取得的 TX 调用栈。外部输入位置（JSON、CSV、XML、正则）另外记录行、列或字节偏移，不把秘密正文写进错误。 |
| 资源所有权 | 文件、socket、进程、线程、数据库连接、语句和游标使用不透明句柄。`close`/`join`/`wait` 的状态迁移、重复调用、别名失效及作用域清理必须逐项定义；自动清理兜底，重要写入仍显式 `flush/close/commit`。 |
| 部分效果 | 写文件、网络流、子进程和事务失败可能已有外部效果；API 文档说明保留的前缀、是否回滚、是否可重试，以及取消后的句柄状态。禁止把异常传播描述为事务回滚。 |
| 文本与字节 | `str` 始终是有效 UTF-8，`bytes` 可包含任意字节。编码转换显式；默认不猜测编码、不悄悄替换非法序列。公开索引必须标明字节、Unicode 标量值或字素簇单位。 |
| 时间与大小 | 时间参数统一使用专用 `duration` 或名称明确的 `*_ms`；负值、溢出和零值含义逐项定义。读取不可信输入须有可配置且有硬上限的大小、深度、计数与超时限制。 |
| 安全与兼容 | 秘密类型与标记为敏感的字段不得进入日志、诊断和默认打印；普通 `str/bytes` 可含应用自行写入的秘密，调用方仍须避免主动输出。新增 API 不改变旧接口的返回类型、错误类别、编码和排序规则；不得兼容时新增带明确名称的接口并记录迁移。 |

依赖选择遵循“复用已用且受维护的实现”。当前固定并静态链接的 Mbed TLS 与 nghttp2 继续复用；正则、Unicode、XML、SQLite、PostgreSQL、Argon2 等新增依赖在实现时锁定版本和校验值、交付许可证，并设置解析资源上限。标准库不自行实现密码学原语、Unicode 数据表或 SQL 协议。

## 3. 集合与数据结构

**保留：** `array/dictionary` 的动态值语义、当前类型化容器、`algorithm` 的现有重载，以及共享引用与 `deep_copy` 的规则。

**终态公开面：**

| 模块/类型 | 终态能力 |
| --- | --- |
| `vector<T>`、`deque<T>` | 构造、长度/容量、索引、插入/删除、切片、快照、双端增删；元素可为用户结构体和嵌套容器。`deque` 的两端增删为摊还 O(1)。 |
| `map<K,V>`、`set<K>` | 哈希查找、插入、删除、遍历与成对条目快照；平均 O(1)，哈希冲突最坏 O(n)。新增 `entries() -> vector<entry<K,V>>`，避免分别取 `keys/values` 时的并发歧义。 |
| `ordered_map<K,V>`、`ordered_set<K>` | 按比较器顺序遍历和范围查询，查找/更新 O(log n)；不把现有无序 `map/set` 的遍历顺序改为有序。 |
| `heap<T>`、`queue<T>` | 继续保留最值堆与 FIFO；增加带稳定序号的优先级条目类型、批量构建和显式自定义比较器。 |
| `algorithm` | 稳定/非稳定排序、`binary_search`、`equal_range`、`unique`、`rotate`、`partition`、`map/filter/fold`、`all/any`、`sum/min/max` 与自定义比较器。 |

设计签名示例：`algorithm.stable_sort<T>(values: vector<T>, compare: fn(T,T)->int) -> void`、`algorithm.binary_search<T>(values: vector<T>, key: T, compare: fn(T,T)->int) -> option<int>`。比较器返回负/零/正并须形成严格弱序；排序中不得修改所排容器。有序容器存活期间，比较器的捕获状态不能改变排序关系。哈希键的相等与哈希必须一致，作为键期间不得修改影响哈希的字段；浮点 NaN 仍不能作哈希键，`+0.0/-0.0` 相等。内置字符串顺序继续按已文档化的 UTF-8 字节序；需要语言学排序时由 `unicode.collator` 显式提供比较器。

排序、过滤及复制类操作明确是原地修改还是返回新容器；原地操作的所有别名观察到相同修改。空容器、越界、溢出、回调抛错与中途修改的结果逐项固定；回调出错时容器可能已部分重排，文档不得承诺原子性。新增容器须接入静态检查、ABI、打印、`any` 显式恢复、`deep_copy` 和循环回收，而不只增加声明。

## 4. 字符串、正则与编码

**保留：** 当前 `string` 的子串、切片、拆分、拼接、ASCII 大小写转换，以及 `format/bytes/encoding` 的既有行为。原 `string.lower/upper` 继续只处理 ASCII，避免改变既有结果。

**新增 `unicode.txh`：** `normalize(text, form)` 支持 NFC/NFD/NFKC/NFKD；`case_fold(text)`、`to_lower(text, locale)`、`to_upper(text, locale)` 分开定义；`code_points(text)`、`graphemes(text)`、`grapheme_count(text)`、`category(code_point)`、`collator(locale, strength)` 与显示宽度接口明确各自单位。规范化、大小写和字素边界采用固定 Unicode 数据版本；运行时可查询该版本。区域设置只影响显式传入 locale 的操作，不能使同一程序的默认比较随机器变化。

**新增 `regex.txh`：** `compile/compile_with_cancel` 显式接收模式、标志和执行限额，返回不透明 `regex_pattern`；`search/match/full_match` 返回包含完整匹配、编号/命名捕获及 UTF-8 字节和 Unicode 标量偏移的 `regex_match`，未命中由 `found=false` 表示。`find_all` 返回完整匹配文本向量；需要逐次捕获时可用 `search` 的字节终点继续查找。`split/replace` 分别返回片段向量和新文本。PCRE2 固定 UTF/UCP 模式及版本；编译错误给出模式字节偏移，执行有输入大小、匹配步数、深度、堆和取消限额。替换模板与零长度匹配规则见[第五部分接口文档](unicode_regex_encoding.md)。

**扩展 `encoding.txh`：** 保留既有严格转换，增加 UTF-32 与增量 `encoder/decoder`；跨块保存部分字符，EOF 时仍有残缺序列才报错。若调用方要求替换或跳过非法字符，必须显式指定策略并能取得替换计数。`bytes` 增加 URL 安全 Base64 与大小受限的分块 Hex/Base64 转换；二进制不隐式转换成文本。正则、Unicode、编码的无效输入统一有可定位的 `parse_error`，并有针对大输入的资源上限。

## 5. 文件、路径、系统与子进程

**保留：** `file` 的整文件文本接口、`file_stream` 的增量读写、`fs/path` 的现有操作，以及 `system/env` 的进程参数、目录和环境变量。当前路径继续是 UTF-8；Windows 上使用宽字符系统 API。

| 模块 | 新增的终态公开能力 | 关键语义 |
| --- | --- | --- |
| `fs` | `stat/lstat`、权限和时间戳、符号链接的创建/读取、目录迭代与筛选、`watch` | `stat` 跟随链接，`lstat` 观察链接本身；递归遍历默认不跟随目录链接，监视事件允许合并和丢失，需支持重新扫描。 |
| `path` | `canonical`、`weakly_canonical`、根/扩展名/文件名分解、平台路径比较 | 与已有词法 `normalize/absolute/relative` 分开；真实路径解析需要访问磁盘并可能失败，不能被用于自动证明权限边界。 |
| `file`、`file_stream` | 整文件二进制便捷接口、`atomic_write_text/bytes`、文件锁和显式持久化 `sync` | 原子替换在同一文件系统的受支持场景下提供；跨卷和断电持久性分别说明。写入失败不得默默留下成功标记。 |
| `system`、`env` | 操作系统/架构/CPU 数/进程 ID、环境快照、用户与临时目录、可用系统能力查询 | 返回时复制快照；环境和工作目录是进程全局状态，改动时记录与并发代码的互斥要求。 |
| `process.txh` | `spawn(options) -> child`、`run(options, limits) -> completed`、`wait/try_wait/terminate/kill`、stdin/stdout/stderr 管道 | 参数按 `vector<str>` 分项传给子进程；默认不启动 shell。退出码、被信号/系统终止及超时分别表示。 |

`process.options` 至少有可执行文件路径、参数、工作目录、环境覆盖/清空模式、三路标准流策略、是否创建独立进程组。`run` 的输出捕获必须有字节上限；`spawn` 可流式读写 `pipe`，父进程不及时读取两个输出管道时不能由标准库内部造成死锁。`wait(timeout)` 超时不暗中杀进程，调用方可显式取消/终止；`run` 的超时策略须在选项中明确。进程对象最后引用消失时关闭父侧句柄，但不会悄悄杀死仍在运行的子进程；需要确定结束结果时必须 `wait`。Windows 命令行引号与反斜杠由库按目标进程规则编码，禁止把参数直接拼接进 shell 字符串。真正需要 shell 的操作使用另一个显式 `shell.run` 接口，标注命令注入风险与平台差异。

文件访问按路径打开前后的竞争无法仅靠字符串 `canonical` 消除；要求安全路径约束的 API 使用目录句柄相对打开及“不跟随链接”选项。文件锁只承诺同机协作进程的约定，不代替数据库事务。`fs.watch` 的取消、关闭与队列溢出都要有可检查的状态。以上操作的 OS 故障归入 `io_error` 或 `process_error`，错误码至少区分 `not_found`、`permission_denied`、`already_exists`、`invalid_path`、`timeout`、`broken_pipe`、`operation_failed`。

## 6. 时间、随机数、数学与统计

现有 `time.unix_millis/monotonic_*` 和 `random.seed/random_int/random_float` 保持兼容；日历时间与单调时钟不得互相替代。

| 模块 | 终态 API 与类型 | 必须固定的规则 |
| --- | --- | --- |
| `time` | `duration`、`instant`、`local_date`、`local_time`、`offset_datetime`、`zoned_datetime`；解析/格式化 ISO 8601、日历加减与时间差 | `instant` 只比较经过时间；UTC 时间与 IANA 时区转换使用随发行物交付的版本化时区数据。夏令时造成的不存在或重复本地时间要求显式选择拒绝、较早或较晚偏移。 |
| `random` | 独立 `generator(seed)`、`next_int`、`next_float`、`shuffle`、`sample`、`choice`、常见分布 | 种子和算法版本固定时结果可复现；每个生成器的状态归调用方所有，跨线程共享须同步。密钥始终使用 `crypto.random_bytes`。 |
| `math` | 三角与反三角、指数/对数、双曲函数、`gcd/lcm`、幂与整数幂、舍入模式、`is_finite/is_nan` | 整数溢出报错；浮点按 IEEE 754 语义，定义域错误与 NaN/无穷大的返回或报错规则逐函数写清；不依赖进程全局 locale。 |
| `statistics` | `mean/median/variance/stdev/quantile`、频数、直方图、流式累计器 | 明确样本与总体公式、空样本、单样本、NaN、无穷大和数值稳定算法；不会默认把整数求和转成会丢精度的 float。 |
| `decimal` | 十进制定点数、指定精度与舍入模式的四则运算、文本转换 | 用于货币等十进制精确计算；小数位、溢出和除法舍入为显式契约，不从二进制 float 隐式构造。 |

`time.sleep` 接受非负 `duration`，可被取消；系统时钟跳变不影响单调计时。格式化与解析的默认区域设置固定，传入 locale 才产生区域差异。统计函数对向量与只读迭代器提供静态重载；巨大数据可用流式累计器而不用先装入内存。

## 7. 网络与协议

**保留：** `httpx` 的 HTTP/1.1、HTTP/2 文本/字节/文件流接口，`websocket` 的 WS/WSS 与二进制流接口，以及 `requests` 当前可用的便捷调用。已公开的 4xx/5xx“正常返回响应”、TLS 默认验证、资源上限和显式关闭规则继续有效。

**新增分层：**

| 层 | 终态公开面 | 失败与资源约束 |
| --- | --- | --- |
| `dns.txh` | A/AAAA、地址解析和反向解析，支持取消、超时与缓存策略 | 地址列表保留顺序及 TTL；解析失败不伪装为空列表。 |
| `socket.txh` | TCP 连接/监听、UDP 收发、半关闭、地址查询、可设置的读写超时 | 收发使用 `bytes` 或受限缓冲；TCP 返回字节数且允许短读/短写；UDP 保留报文边界与截断状态。 |
| `tls.txh` | 客户端/服务端安全流，系统信任或显式 CA、主机名校验、客户端证书、ALPN | 验证默认开启，证书/私钥以不透明资源持有；关闭 TLS 流的规则不含明文数据泄露。 |
| `httpx` | 可复用客户端连接/连接池、HTTP/1.1/2/3 协议协商、服务端路由与并发、真正的读写流、压缩、代理与 TLS 配置 | 保留现有显式 HTTP/2 接口；协议升级/降级策略由选项决定。头、正文、并发流数、压缩比和总时间都有上限。 |
| `websocket` | TLS 服务端、同 HTTP 监听器上的 Upgrade、ping/pong、关闭原因、异步收发 | 消息与流模式都保留文本 UTF-8 和二进制区别；心跳、空消息与正常关闭不混淆。 |
| `requests` | 会话连接池、流式响应迭代、上传/下载、代理、自定义 CA/客户端证书、完整 Cookie 处理与可配置重试 | 把当前的 `unsupported_option` 逐项落实为实际行为；自动重试仅在请求幂等且正文可重播时执行。 |

HTTP/3 使用独立、受维护的 QUIC/TLS 实现；协商失败或网络阻断时，只有允许降级的调用才回到 HTTP/2/1.1。HTTP 服务端对同一连接上的多个请求/流实施限额、背压和公平调度；TX 回调进入语言运行时前恢复正确的线程/任务上下文。同步接口可包装异步实现，但不能通过每个连接一个无限制线程来“模拟”并发。客户端的连接、发送、首字节、空闲读取和总截止时间分别可设；用户取消须中止正在阻塞的 I/O 并关闭或复用安全状态的连接。

HTTP 请求/响应中的状态码、头、Cookie、重定向和压缩遵循相应 RFC；跨源重定向不得转发认证信息。代理支持 HTTP CONNECT 和 HTTPS 场景，代理认证须走秘密值容器。TLS 默认校验证书链与主机名；允许自定义信任锚，但不提供悄悄忽略验证错误的默认路径。低层 socket 和协议解析面对不可信输入要限制内存、句柄、时间与递归深度，并对非法帧/请求进行专项验证。

## 8. JSON、CSV、XML 与序列化

已有 `json` 严格区分合法 `null` 与解析失败，保留它的 `any/array/dict` 映射、128 层嵌套限制、字段访问和稳定对象输出。新增格式不应通过先转换成 JSON 文本再解析来共享实现。

| 模块 | 终态接口 | 输入/输出契约 |
| --- | --- | --- |
| `json` | 保留现有接口，增加基于 `text_stream`/`binary_stream` 的增量读取与生成、可选 schema 校验 | 默认严格 UTF-8、有限数字和明确大小上限；流式解析错误报告行列与字节偏移。 |
| `csv.txh` | `reader(stream, dialect)`、`next_row() -> option<vector<str>>`、`writer`、`write_row`，以及整文本便捷接口 | 默认 RFC 4180；分隔符、引号、换行和表头策略显式配置。嵌入换行、空字段、最后无换行、BOM 与编码都可区分；行宽和字段长度有限额。 |
| `xml.txh` | 拉取式 `reader`、树形 `document`、命名空间/属性/文本访问、`writer` | 支持 XML 1.0 与 UTF-8/UTF-16；保留元素顺序、命名空间 URI 与文本内容。默认禁止 DTD、外部实体、网络实体和 XInclude；深度与实体扩展有上限。 |
| `cbor.txh` | `encode/decode` 与流式 reader/writer，支持规范化编码 | 以带类型的二进制数据互通；整数、浮点、字符串、字节、数组、映射、布尔和 null 有明确对应；拒绝不符合规范的重复键及无限制嵌套。 |
| `serde.txh` | 为标记的 TX 数据结构生成 JSON/CBOR 编解码器，提供 `serialize_json<T>`、`deserialize_json<T>`、`serialize_cbor<T>`、`deserialize_cbor<T>` | 结构体字段拥有稳定名称/编号、必需或可选属性、默认值和 schema 版本。不能序列化函数、线程、文件、socket、数据库句柄或密钥对象。 |

`serde` 的字段元数据属于编译期声明，代码生成时固定编码器和解码器，不在运行时按字段名遍历任意对象。向后兼容规则为：新增字段必须可选或有默认值；删除字段保留其编号；字段类型改变需要新编号或显式迁移；未知字段按 schema 策略忽略或保留，绝不悄悄映射到另一个字段。反序列化先校验长度、类型、深度和字段约束，再交付完整对象。没有“反序列化任意类并执行构造器”的入口。

CSV、XML 和 CBOR 的解析异常统一归入 `parse_error`，携带格式名、可定位位置及稳定错误码。输出写入流可能部分成功，调用方可选择先生成到内存/临时文件后原子替换。公开文档分别给出小数据与大数据流程，不要求大文件全量驻留内存。

## 9. 并发、异步任务与进程间通信

终态并发模型由**显式共享约束 + 有界任务/通道 + 结构化生命周期**组成。新增并发不改变现有单线程 TX 程序的求值顺序、共享引用语义和未捕获错误退出规则。

| 模块/类型 | 终态公开面 | 核心规则 |
| --- | --- | --- |
| `thread.txh` | `spawn(fn()->T) -> join_handle<T>`、`join`、`detach`、线程标识 | 回调和捕获值必须满足 `Send`；可变对象跨线程共享还必须经 `Sync` 保护。线程错误由 `join` 重新交付，未 join 的错误进入显式错误回收策略。 |
| `task.txh` | `scope`、`spawn`、`wait`、`cancel`、`deadline`、定时任务与任务组 | 作用域退出前等待或取消其子任务，不留下隐形后台工作；取消是协作式且能唤醒阻塞 I/O。取消不能伪装成正常空结果。 |
| `channel.txh` | `bounded<T>(capacity)`、`send`、`recv -> option<T>`、`close`、`select` | 队列有界，生产者遭遇背压；关闭后已入队元素仍可取完，空且关闭才返回 `none`。等待可取消且不会丢失已交付消息。 |
| `sync.txh` | `mutex<T>`、`rw_lock<T>`、`condition`、`semaphore`、`once`、`atomic<int/bool>` | 锁卫士离开作用域自动释放；原子内存序和公平性有文档。持锁期间不得跨 `await`；锁顺序死锁由调用方避免。 |
| `ipc.txh` | 本机命名管道/Unix 域套接字、带长度前缀的消息流、子进程三路管道 | 发送/接收区分 EOF、半包、超时和取消；消息大小有上限，不把反序列化当作代码执行。 |

类型系统需要在编译期标记 `Send`（可移动到另一线程）与 `Sync`（可安全共享只读或受控访问）：不可变标量、`str`、`bytes` 可以安全传递；现有可变 `array/dict/vector/map` 的普通共享别名不能直接跨线程写，须唯一移动或放入同步容器。网络/文件/数据库句柄按各自驱动声明可否跨线程，不能仅因是整数 ID 就认定安全。引用计数、循环回收安全点、析构回调与错误传播均必须对多线程正确；编译器不能把跨线程回调当作普通同步调用优化。

任务运行器使用有界工作线程和 I/O 事件循环；异步文件、socket、HTTP 和数据库调用返回 `task<T>`，`wait` 提供同步桥接。对于需要大量并发 I/O 的代码，语言提供 `async` 函数与 `await` 表达式；二者的静态返回类型、异常传播、取消和局部变量生命周期由编译器确定。阻塞式旧接口在工作线程中可以继续使用，但不能在事件循环线程上无界阻塞。任务结束后必须能获得成功值或原始错误，任务取消后外部副作用的完成程度由各模块报告。

`process` 和 `ipc` 共同完成进程间通信：`spawn` 可把标准流连接为管道；本机消息流可用 `cbor` 传结构化数据。跨进程协议必须有版本、消息长度、EOF 和重启处理，不通过共享内存直接传 TX 对象句柄。若提供共享内存，另设明确的布局、原子同步与生命周期 API，不能复用普通容器地址。

## 10. 数据库与事务

终态至少交付内嵌 `sqlite` 和客户端/服务端 `postgres` 两种驱动，公开统一的 `db.txh` 连接、语句、游标、事务与池契约；驱动差异通过能力查询和驱动专属选项显式呈现，不制造“所有 SQL 方言相同”的假象。

| 类型/操作 | 终态行为 |
| --- | --- |
| `db.open(options) -> connection` | 选定 SQLite 文件或 PostgreSQL 地址；连接超时、TLS/证书、只读、忙等待和字符编码在选项中明确。默认使用 UTF-8。 |
| `connection.prepare(sql) -> statement`、`statement.bind(index, value)` | 参数与 SQL 文本分离，不支持通过字符串插值代替绑定。SQLite 和 PostgreSQL 的 SQL 占位符语法分别保持原生规则；索引在 API 中从 1 开始。 |
| `statement.execute() -> execution` | 返回影响行数与可取得的插入标识；不把查询行一次性全部装入内存。 |
| `statement.query() -> cursor`、`cursor.next() -> option<row>` | 逐行读取；`row` 提供列名、列序号与 `get_int/get_float/get_str/get_bytes/get_bool/get_decimal/get_datetime`，SQL NULL 通过 `option<T>` 表示。 |
| `connection.begin(isolation) -> transaction` | `commit` 后持久化、`rollback` 后撤销；作用域异常或未提交时自动回滚。事务不能从另一连接执行，嵌套使用明确的 savepoint。 |
| `db.pool(options) -> pool`、`pool.acquire(timeout)` | 有界连接数与等待队列；借出的连接归还前清理未完成事务、游标及临时状态。 |
| `db.migrate` | 版本号、校验值和按驱动声明的事务边界；同一迁移不得在不同客户端并行重复执行。 |

`db.value` 是显式标记的动态边界，覆盖 NULL、布尔、64 位整数、有限/非有限浮点的驱动规则、UTF-8 文本、字节、`decimal` 和时间类型。读取字段的类型转换必须显式；列缺失、NULL、类型不符与无行分别可辨。结果游标、语句、事务与连接的关闭次序固定，关闭连接时不得留下仍可误用的别名。一个连接一次只执行一个未完成游标，除非驱动明示多活动结果支持；并行查询借用池中不同连接。

SQLite 使用受维护的 amalgamation，限定文件路径、journal/WAL、`busy_timeout` 和线程模式；PostgreSQL 使用受维护的客户端库，默认验证服务端证书与主机名，密码通过秘密值而非日志或 URL 明文传播。数据库错误为 `database_error`，`code` 区分连接、认证、约束、超时、取消、冲突、类型和事务状态；底层 SQLSTATE/扩展码可另行读取，但不代替稳定的 TX 错误码。失败语句在事务中的可继续性遵循驱动状态：PostgreSQL 出错事务必须回滚到 savepoint 或整体回滚；库不得让后续调用误以为事务仍可正常提交。

仓库目前的 `scripts/check_*.py` 和 `tests/` 用于验证编译器本身；终态另给 TX 用户提供正式工具与 API。

| `txc test` | 发现并编译测试、按稳定顺序运行、可筛选/并行/设超时、汇总及机器可读报告 | 每个测试或测试组可进程隔离；失败、崩溃、超时和编译错误分别计数，退出码反映总体结果。 |

测试发现机制通过显式测试注册或编译期标记实现，不能靠运行时扫描函数名；`assert_*` 在编译期或生成代码中捕获调用位置。性质测试的随机种子记录到失败报告，最小化反例时限制步数与内存。日志默认不初始化远程输出或后台网络连接；用户显式配置 sink。性能分析可观测编译器生成的代码、标准库 C ABI 和原生耗时，报告中区分各层而不把采样结果当作精确逐函数计数。

## 12. 密码学、密码处理与证书

**保留：** `crypto.random_bytes`、SHA-256/SHA-512、HMAC-SHA256、HKDF-SHA256、PBKDF2-HMAC-SHA256 和 `TXCG` 格式的 AES-256-GCM 单段加解密。已有 `bytes` 密钥的清零限制在[密码学标准库设计](crypto.md)中已说明，不能仅靠文档把普通 `bytes` 宣称为安全密钥容器。

| 模块/类型 | 终态能力 | 安全契约 |
| --- | --- | --- |
| `secret_bytes` | 不透明、不可打印的秘密缓冲，受控导入/导出和显式销毁 | 不进 `any`、日志、普通序列化或默认 `deep_copy`；在可行平台锁页并在释放时清零所有受控副本。操作系统换页/崩溃转储等限制需如实说明。 |
| `password.txh` | Argon2id `hash_password/verify_password/needs_rehash`；参数存入标准 PHC 字符串 | 生成独立随机 salt，验证时固定时间比较结果；内存、时间和并行度有安全下限与资源上限。现有 PBKDF2 保留用于协议兼容/派生，不作为新密码存储默认值。 |
| `crypto` | 流式 SHA-2/HMAC、增量 KDF、带版本和块序号的大文件认证加密、密钥轮换标识 | 每块 nonce 唯一，认证绑定文件头、顺序、最终块及上下文；解密认证成功前不向目标公开不可信明文。 |
| `public_key.txh` | Ed25519 签名/验签、X25519 密钥交换、标准化密钥导入导出 | 私钥放在不透明句柄；算法与编码显式；不提供裸密钥交换后直接当对称密钥使用的便捷入口，须接 HKDF。 |
| `x509.txh` | PEM/DER/PKCS#12 读取、链构建、主机名/用途/有效期验证、系统与自定义信任锚 | 证书过期、名称不匹配、用途错误、未知签发者和撤销状态可区分；私钥密码不出现在异常或日志。 |
| `tls` | 与 `socket/httpx` 共用的证书、信任、客户端身份和 ALPN 配置 | 默认验证、使用安全协议/密码套件，禁用过时算法和降级；异常不能交付未经验证的应用数据。 |

哈希不代替 MAC，Base64/Hex 不提供保密性。`crypto.encrypt/decrypt` 的原 `TXCG` 格式保持可读可写；大文件格式使用新魔数和版本，不把每块单独调用旧接口后拼接成流。流式解密在整体认证完成前先写入受控临时文件，验证成功后才提交目标文件，避免向调用方交付未认证的明文。密钥随机数只来自操作系统支持的密码学随机源，不复用 `random` 的可设种子生成器。签名、Argon2id 和 X.509 实现采用经过维护的第三方库或现有 Mbed TLS 能力，版本与许可证纳入发行物。验签、认证失败和密码不匹配的处理须避免可观察的内容差异与敏感数据回显。

## 13. 实现边界、兼容与交付关系

各能力按以下依赖关系集成，关系用于确定先后约束，**不缩减终态范围**：

1. 类型系统与运行时补足参数化容器、`option/result`、闭包、`Send/Sync`、异步任务、资源句柄与调用栈。每一种新增类型先明确静态规则、C ABI、所有权、`any` 边界、`deep_copy` 和错误清理，再接入使用它的模块。
2. 文本/字节、时间、错误和流是跨模块公共基础。CSV/XML/JSON/CBOR、文件、网络和数据库复用同一套 UTF-8、分块、大小上限、取消与稳定错误码，不各自发明“空值代表错误”的协议。
3. `socket/dns/tls` 支撑 `httpx/websocket/requests`；`thread/task/channel` 支撑服务端并发、异步 I/O 和数据库池；`process/pipe` 与 `ipc`、`cbor` 组合。同步 API 保持现有行为，异步 API 以独立函数/类型交付。
4. 安全边界贯穿所有模块：`secret_bytes` 进入数据库凭据、代理认证、TLS 私钥与密码处理；日志、错误和调试输出默认遮蔽。各模块仍负责本地限额与输入验证，不能只依赖上层调用方。
5. 每个新增模块随 `.txh`、C++23/必要的 TX 实现、直接 ABI、构建依赖、中文参考文档、示例和聚焦验证一起交付。`tx/stdlib/` 只含接口；根目录 `tx/` 保留编译器、静态库、链接组件、许可证和运行依赖。

依赖和平台实现作如下选择；具体发行版本在开发对应模块时固定并记录校验值，不以“系统恰好安装了某库”作为发行条件。

| 领域 | 依赖或系统后端 | 交付要求 |
| --- | --- | --- |
| Unicode/时区 | ICU4C 与随发行物固定的 Unicode、IANA 时区数据 | 公开数据版本；区域差异仅经显式 locale/zone 进入结果。 |
| 正则/XML/CBOR | PCRE2、libxml2；CBOR 采用仓库内实现 | CBOR 8.4 的受限核心确定性编码不引入 QCBOR；新增静态库仍须随工具链交付许可证与资源限额。 |
| 数据库 | SQLite 官方 amalgamation、PostgreSQL libpq | 明确驱动版本、TLS 能力、线程模式和事务语义。 |
| 密码学 | 现有 Mbed TLS；Argon2 参考实现；libsodium 提供 Ed25519/X25519 | 只在支持的算法入口使用；标准向量和跨库互操作随模块验证。 |
| 网络/任务 | Windows IOCP 与系统 socket；HTTP/3 使用 MsQuic；其他平台采用等价事件后端 | 公开相同的取消、超时和错误契约；平台缺失时在构建或初始化时明确报告能力不可用。 |

第五部分锁定 Windows x64 的 MSYS2 mingw64 包：ICU4C `78.3-4`（包 SHA-256 `8486a018aca2e56d1fcd2eed2069011f2e1da02e03af72b38916ee06cbe7203f`）和 PCRE2 `10.48-3`（包 SHA-256 `c67c23f448693e8c9cc3973872372dabec2abdf6afacb563096f7eb0e6837f57`）。构建时按哈希验证下载包；ICU 导入库和 PCRE2 静态库归档到 `libtxstdlib.a`，ICU 运行时 DLL 及许可证随 `tx/` 交付。ICU 静态库与当前 CLion MinGW 运行库存在 ABI 冲突，故使用固定版本 DLL；配套 `libstdc++` 与 `libgcc` 锁定为 MSYS2 `16.2.0-4`（包 SHA-256 分别为 `3d4c3faf4c2c5c7a851ff12214ddcbf8c0d6df0964fc1d3ebd8c38f227183034`、`d615f6a8536ca16b1f049daea1fa440a3b7a405449ec0e93ad6106db43682d54`），`libwinpthread` 锁定 `14.0.0.r426.g4564ee4b5-1`（包 SHA-256 `543017ce2731292b215bf1d36fd70a86d8a8d5ed0afba9d3db9fff89804cda71`）。打包时仅将两份 ICU DLL 的同长度导入名改为私有的 `libstdc++-u.dll`，TX 程序继续使用原编译器的 `libstdc++-6.dll`，两套运行库只通过 ICU C ABI 交互。Unicode 数据版本由随库提供的 `unicode.version()` 查询，不依赖宿主机 ICU 或区域设置；旧 `string.lower/upper` 仍是 ASCII 行为。

第八部分的 XML 后端固定 libxml2 `2.13.8` 源码归档（SHA-256 `277294cb33119ab71b2bc81f2f445e9bc9435b893ad15bb2cd2b0e859a0ee84a`），构建时校验哈希并静态归档到 `libtxstdlib.a`；`tx/LIBXML2-LICENSE` 随包。禁用网络协议、动态模块与 XInclude 构建选项，解析入口还关闭 DTD 装载、实体替换与验证；接口限额和具体语义见 [XML 模块说明](xml.md)。

`txc`、`.txh`、标准库静态库和运行时 ABI 需要共同的兼容版本/指纹；混用不匹配产物应在编译或链接前报告，而不是等待程序崩溃。构建脚本校验所有源码归档，保留许可证与依赖清单；安装后的示例只依赖交付目录内和目标系统已声明的组件。

旧 API 的兼容处理：

- `string.lower/upper`、`random.seed`、`time.unix_millis`、`httpx.send_http2`、`crypto.encrypt`、旧具体结果结构体等继续存在并遵守旧语义。新 Unicode、实例随机数、日历、协议协商和 `result<T>` 用新名字/重载，迁移说明展示等价与不等价情况。
- 不能在旧函数中突然增加自动重试、自动重定向、隐式编码、失败吞咽或不同排序顺序。需要弃用时先提供机械可检查的替代接口、静态警告和明确的移除条件；现有示例仍可编译运行。
- 已有 `requests` 的 `unsupported_option` 参数在终态必须真实实现或以明确的新 API 替代，并提供兼容层；不能继续把参数接受下来后忽略。数据库、网络和文件配置不得在诊断中展开凭据。
- 改动语法或类型规则时，先更新 `docs/syntax.md` 和示例，再修改词法、语法、语义与代码生成；不得仅由某个新标准库函数反推语言规则。

## 14. 终态验收矩阵

| 类别 | 必须可完成的真实场景 | 需要固定的错误/边界证据 |
| --- | --- | --- |
| 集合与数据结构 | 保存用户结构体、按自定义顺序稳定排序、哈希/有序查询、队列与堆组合计算 | 空容器、重复键、NaN、比较器错误、迭代修改、共享与独立复制、溢出 |
| 字符串与编码 | 多语言规范化和字素截取、Unicode 正则提取、跨块 UTF 编码转换 | 非法 UTF-8、残缺尾块、零长度匹配、超限正则、位置单位一致 |
| 文件与系统 | 大文件分块处理、原子保存、符号链接与权限检查、传参启动进程并同时捕获两路输出 | 不存在/拒绝访问、短读短写、取消和超时、管道背压、跨卷限制、句柄清理 |
| 时间与数学 | 时区转换与夏令时歧义处理、可复现随机模拟、稳定统计与十进制金额计算 | 负时长、日历溢出、NaN、空样本、舍入、随机算法版本 |
| 网络 | HTTP/1.1/2/3 客户端及并发服务端、WS、TCP/UDP、代理、TLS 双向认证、流式大文件 | 不可信帧、慢连接、大小/压缩比上限、取消、证书失败、重定向凭据保护、资源释放 |
| 数据格式 | JSON/CSV/XML/CBOR 读写大数据与跨 schema 版本迁移 | 重复键、非法字符、深度/长度超限、XML 外部实体、缺字段/未知字段、半写入 |
| 并发 | 多任务并发请求、有界通道消费、线程同步、进程间版本化消息 | 数据竞争静态拒绝、关闭/取消/超时、任务失败传播、GC 与析构、无孤儿任务 |
| 数据库 | SQLite 本地事务、PostgreSQL TLS 连接、参数查询、流式结果、池化和迁移 | SQL 注入防护、NULL 与无行、约束冲突、回滚、断连、池耗尽、关闭后误用 |
| 测试与调试 | TX 用户运行单元/性质测试、查看结构化日志与 TX 源码级 CPU/内存报告 | 失败位置、隔离/超时、可复现种子、并发日志完整性、秘密遮蔽、报告退出码 |
| 安全 | Argon2id 密码验证、Ed25519 验签、X.509 验证、大文件认证加密与密钥轮换 | 标准向量、篡改/错误密钥、证书用途与主机名、nonce 唯一、明文不提前交付、清理限制 |

对每行还需通过三类共通检查：公开签名的静态类型与重载诊断；正常路径及典型外部失败；资源关闭、错误传播与部分效果。网络、解析器、数据库协议和密码学入口需要针对不可信输入的模糊测试及相应标准向量/互操作验证。并发需要线程与取消竞态验证。性能目标以与等价 C++23 任务的重复测量和可解释的开销分解表述，不能用单次基准数字代替正确性。

完成的判定是十行均有公开 API、源码实现、可复现的聚焦证据、中文接口文档和可运行示例，并且跨模块场景能闭合：`文件 → CSV/XML/JSON → 数据库`、`HTTP/WS → 并发任务 → 数据库 → 日志`、`密码输入 → Argon2id/证书 → TLS/安全存储`。仅有接口声明、单个本机 smoke 或“计划以后补充”均不满足终态交付。

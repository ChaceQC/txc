# 内存管理与循环回收

数组、字典、结构体和类对象是共享引用类型。普通赋值、传参和返回只增加引用；`deep_copy(值)` 显式复制对象图。字符串及基本值保持现有值语义。例如 `int a = 2; int b = a; b = 3` 后，`a` 仍为 `2`。

## 回收规则

- 无环对象在最后一个引用释放时立即析构。类对象的 `deinit` 仍按最派生类到祖先类的顺序执行。
- 运行时记录复合对象的弱引用，不因记录本身延长对象寿命。复合对象分配达到阈值后的下一个安全点，以及程序退出时，检查仍存活的对象图。
- 回收器从每个对象的引用数扣除其他复合对象字段或元素对它的引用。剩余外部引用大于零的对象及其可达对象仍存活；其余对象构成不可达对象图。回收器清除这些对象之间的引用，使引用计数完成释放。
- 不可达类对象在清除字段前执行一次 `deinit`，析构期间字段仍可读取。若 `deinit` 把对象重新放入仍可达的位置，回收器重新检查可达性并保留它；同一对象不会再次执行 `deinit`。
- 回收时间由安全点决定，不保证在最后一个外部引用消失时立刻发生。循环引用无需由程序手动断开。

回收器只处理 `.tx` 运行时创建的复合对象。运行时错误退出前仍会清理已登记的句柄，并回收余下的不可达循环对象。回收器运行期间不会再次启动自身。

例如下面的 `a` 和 `b` 指向同一个数组，第 0 个元素又指回该数组；函数返回后，回收器可在后续安全点回收这个环：

```tx
def example()
{
    array a = [1, 2]
    auto b = a
    b[0] = a
}
```

循环回收只影响对象寿命，不改变 `print` 对自引用容器的递归深度限制。

可运行的[循环回收示例](../examples/cycle_collection.tx)覆盖类、数组、字典和 `deep_copy` 生成的环；[复活示例](../examples/cycle_resurrection.tx)展示 `deinit` 把对象重新变为可达的情况。

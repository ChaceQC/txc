# 性能优化 12–14：游标、算术、参数展开与对象图

日期：2026-09-29。实施起点 `85433b37ac702426b0277ce1803793ff1ccf0e48`，初始工作树干净。12.1–12.4、13.1–13.5、14.1–14.4 已实施，定向行为与结构检查通过。递归仅有小幅变化，动态展开未获得稳定提速；本记录不宣称所有项目均达到完整 C++ 对照的倍率门槛。

## 实现范围

内部契约先记录在 [performance_12_14.md](../../docs/performance_12_14.md)，公开语法、接口、共享引用、诊断栈、浮点规则和错误类别保持。

| 计划项 | 实现与边界 |
| --- | --- |
| 12.1–12.3 | 旧机器码确认局部标量 next 已使用 present/value ABI；新实现复用这一路径，在整个函数用途证明通过的局部 int/float/bool snapshot 上缓存 32 字节游标视图，直接 load 元素并立即 store index。closed 优先于耗尽；首次读空写入 exhausted。别名、传参、返回、deep_copy 来源、live_iter 和复合元素保留完整 ABI。允许混用普通 next/close，仍操作同一状态；不能提升的检查继续逐次执行。 |
| 12.4 | 无容器写入、无未知调用的标量 foreach 借用已有局部拥有者，避免外层每次扫描 clone/release。1k/100k 共读取相同的 100 万元素，C++ 使用 int64_t 并保留相同输入下的加法溢出检查。机器码确认扫描循环仍有 `jo`，未通过去掉溢出语义来向量化。 |
| 13.1 | 已证明安全的整数除法直接 sdiv；其他整数除法先检查零及最小整数/-1，浮点除法检查正负零再 fdiv。仅错误分支调用旧 ABI。最小整数 `% -1` 仍为 0；NaN 和无穷传播保持，无 fast-math。 |
| 13.2–13.3 | 常量、不可改写局部、for 上下界和简单 if 条件产生保守区间；表达式内部的 ++/--、赋值、解包、同名遮蔽等使证明失效。无证明继续 overflow intrinsic。for 末端先判断终点，最大整数边界不会额外自增。诊断位置只在同一基本块去重，分支边界重新记录；递归逻辑帧、错误位置和 stack_trace 保留。 |
| 13.4 | 数组/字符串键字典字面量在形状、参数类型和冲突均可证明合法时直接绑定，表达式仍按源码顺序执行。固定参数不再构造展开容器；可变参数仍物化独立浅复制容器。动态 any、重复/不支持的键、缺参/多参及类型失败退回原检查。 |
| 13.5 | 固定参数名表改为只读全局常量，直接读取已绑定槽，免去重复索引检查和可写地址导致的登记。绑定结果按实际值追加，避免纯标量结果无故登记。动态实参仍按原类型/键规则检查，目标仍是已解析函数。后续 ** 表达式可能修改 * 源时使用顺序快照的通用路径。 |
| 14.1–14.2 | record_field 增加静态复制类别，标量直接复制固定槽；已知引用进入对应结构体/类/数组/字典/向量/容器/迭代器/闭包分支。文本/bytes 保持值/不可变共享规则。动态叶子优先识别标量；外部资源限制拆分到独立文件。共享及成环对象仍先登记副本，再填充字段；未省掉身份表。 |
| 14.3–14.4 | 描述扫描排除纯值向量/迭代器；无对象边的迭代器跳过登记但实际创建仍计入分配。GC 在登记锁内先按 owner 筛选，直接锁定相关弱引用，边存入连续数组。工作图仅在单轮持有强引用；析构后释放旧图并重新判断可达性。执行门、阈值、错误清理和一次 deinit/复活协议保持。 |

## 定向验证

`python -X utf8 scripts/check_performance_12_14.py` 最终通过，15 个 TX 场景及 IR 检查，输出见 [checks.json](checks.json)。未执行无关模块的全量套件。

- 新增：标量 snapshot、空游标、关闭/永久耗尽、next 后报错继续推进、共享别名、live 修改与复制；整数/浮点除零、最小整数溢出、最大循环端点、NaN/无穷、可变局部失效证明；字面量展开顺序、默认值、动态展开、可变参数独立身份、后续实参改变原数组，以及五种展开错误；混合固定字段、共享子对象、对象向量和数组自环复制。
- 复用：跨模块迭代器、statistics 的游标消费、普通参数展开、错误栈、类/数组/字典环、复活、错误清理、任务对象图、闭包环和第 09–11 项混合字段场景。循环析构逐条核对次数；复活严格核对一次析构及后续字段可读。
- IR：稳定 snapshot 无 next_scalar 调用，别名/live 保留；整数/浮点正常路径为 sdiv/fdiv；安全递归减法和已证明乘法无 overflow intrinsic，可变局部保留；字面量固定参数无 call_bind/array_new，动态绑定读取 bound_slot。
- [机器码与调用清单](machine_calls.json) 确认旧程序使用 next_scalar，新 snapshot 无逐元素 next ABI；小向量扫描无 clone；常量除法无 div ABI；静态展开无 call_bind；递归的安全减法无 sub 错误入口。保留 [旧机器码](old_hotpaths.asm) 和 [新机器码](new_hotpaths.asm)。

构建期间发现 statistics 直接访问旧游标字段，已同步接入新状态并通过其定向用例。性能路径的任何字段/ABI 变更均已重新构建桥接对象。

## 同轮性能

环境：AMD Ryzen 7 6800H，Windows 10.0.26200 x64。编译器/标准库为 GCC 13.1 Release；TX 程序为发布 clang 23.1.2 `-O3`；独立 C++ 对照为 GCC 13.1 `-std=c++23 -O3`。未固定 CPU 亲和性或电源状态，未删除慢样本。

[paths.tx](paths.tx) 在修改前构建并保留程序和 DLL，之后同源码构建候选。源码 SHA-256 为 `c17eef06c035eb80d89eb693e9eb90bfecbacea60c19ea0ddf005a8bd1a0b9f3`。预热 1 次，正序/倒序交替 5 轮，每次核对校验值；下表为程序内部耗时中位数（ms），提速为旧/新。

| 项目 | 旧 TX | 新 TX | 提速 |
| --- | ---: | ---: | ---: |
| snapshot，10 次创建并消费 100k 元素 | 14.327 | 3.291 | 4.35× |
| vector，1k × 1000 次扫描 | 0.481 | 0.238 | 2.02× |
| vector，100k × 10 次扫描 | 0.272 | 0.261 | 1.04× |
| 整数常量除法，100 万次 | 2.895 | 0.352 | 8.22× |
| 递归，2 万次、深度 100 | 7.298 | 6.963 | 1.05× |
| 静态展开，2 万次 | 83.966 | 16.239 | 5.17× |
| 动态展开，2 万次 | 15.410 | 15.742 | 0.98× |
| 固定混合字段 deep_copy，10 万次 | 355.159 | 73.240 | 4.85× |

动态展开中位数慢约 2.2%，不记为提速；递归约 5% 的差异也不足以认定明显稳定收益。纯标量扫描仍保留加法溢出分支，未生成 SIMD 求和。独立 int64 C++ 扫描为 0.519/0.528 ms，编译器及分支布局不同，因此不把 TX 更低的时间解读为通用算法优势。vector_index 未新增独立计时；索引读写实现未修改，大向量扫描本轮保持性能。

## 通用对象图与内存

[graph_core.cpp](graph_core.cpp) 每轮创建 128 节点，每节点一个 int64 和两条任意共享/循环边，复制后释放所有外部根，再显式回收；共 100 轮。TX 运行时核心分别链接基线和候选静态库；独立 C++ 使用 variant、shared_ptr、身份表及通用外部引用计数/可达性扫描，不按单节点自环特判。两边都有自环和共享边，复制后验证新身份及环。

| 核心耗时中位数（ms） | 旧 TX 运行时 | 新 TX 运行时 | 独立 C++ |
| --- | ---: | ---: | ---: |
| 图复制 | 12.004 | 8.194 | 1.955 |
| 图回收 | 9.456 | 5.743 | 6.049 |

图复制旧/新为 1.46×，新 TX/C++ 为 4.19×；图回收旧/新为 1.65×。这是数组图核心，未包含用户 deinit、复活、其他资源或完整 TX 调用外围，不能作为完整类对象图的统一倍率门槛。

每次进程的最大单轮回收暂停（微秒）：旧 `[249,130,144,190,148]`，新 `[100,102,98,93,118]`，独立 C++ `[104,124,182,89,155]`。这是每个进程中 100 次回收的最大值，不是延迟分位数。五次进程的最大峰值工作集：旧 5,808,128 字节，新 5,779,456 字节，C++ 5,664,768 字节；最大 PeakPagefileUsage 分别为 1,277,952、1,228,800、1,265,664 字节。这里没有证据宣称大幅内存下降；计数包含进程及运行库，不等同于图净堆占用。

所有轮次、执行顺序、资源样本与最终哈希见 [samples.json](samples.json)。收尾前参数表/登记调整的首轮结果保留在 [samples_initial.json](samples_initial.json)，未与最终候选混用。未新增独立 deinit 性能计时，析构与复活结论来自行为断言。

`scripts/build.ps1 -Incremental` 构建成功，产物位于 `tx/`。最终 ABI 指纹为 `0801b98c540a007c9f530f12b3891edf363c71445ef5f3ab5c857e7f036c15a2`，覆盖新增公共复制种类、record_field 布局、iterator.hpp 和 LLVM 生成文件。旧编译器不能与新静态库混用。

`scripts/check_package_compatibility.py` 的正常包及 4 种错配通过。三个桥接对象均在归档中恰好出现一次，提取字节与最终构建对象一致，见 [bridges.json](bridges.json)。实现和测试摘要见 [source_manifest.json](source_manifest.json)，基线哈希见 [baseline.json](baseline.json)。

产物核对后尝试清理临时 `build/`：命令包含绝对路径、普通目录及受版本管理文件检查，但自动审批在执行前拒绝，返回 `blocked by policy`。清理命令未执行，因此 `build/` 仍保留；没有通过其他方式绕过这一限制。发布产物位于 `tx/`，不受影响。

重现顺序：在起点构建工具链，带入本目录源码，运行 `baseline.py`（拒绝覆盖基线，同时保存旧静态库）；应用修改并整体构建，运行定向检查及包兼容检查，再运行 `measure.py`、`inspect.py`。产物核对后清理临时 `build/`，保留 `tx/` 和被忽略的 `tx_build/performance_12_14/` 对照材料。

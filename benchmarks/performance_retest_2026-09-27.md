## 当前状况

- 基础整数控制流已恢复到接近 C++ 的量级：`scalar_control` TX 0.17 ms / C++ 0.2423 ms，`while_logic` TX 0.16 ms / C++ 0.1759 ms。近期审计中的迭代器快照从 92.56 ms 到 1.77 ms，标量 `option` 从 84.59 ms 到 0.025 ms。
- 热点仍集中在递归、类方法、虚调用、类型化容器、函数值与闭包。独立 500 万次随机数负载 TX 103 ms / C++ 8.5615 ms，比之前的 TX 38 ms / C++ 9.03 ms 明显慢。
- `mini-filesystem` 五组 TX 中位数比 2026-09-25 同源码记录高约 97%～182%；两轮的题目源码和输入哈希相同，C++ 同轮中位数基本保持相近量级。这是明确的本机性能回退观察，原因未定位。`not-yet-on-stage` 五组高约 3%～10%，小幅差异需考虑系统波动。

## 校验与边界

- 22 项语言特性的 TX/C++/Python/Java 在 7 轮均符合预期校验值，完整四语言表见上方链接。标准库 TX/C++ 共通项目校验值一致，浮点以数值比较；新增负载的每个程序校验值在各轮稳定。
- 全部测量均在同一组 TX 编译器与静态库 SHA-256 下进行。当前结果仅代表本机 Windows；C++ 极短循环优化、Java 进程内 JIT、文件系统缓存与本机回环都会影响数值。每模块只测一个正常路径，不能外推整个 API。
- 37 模块审计中的 `compute.cpp` C++ 对照使用本工作区此前以 GCC Release 构建的程序，源码时间戳早于该程序且本轮未变；完整重建后临时依赖目录被清理，无法在本轮重编含 mbedTLS 头文件的该对照。其他已列出的 C++ 基准按各自入口构建或使用同一份既有对照源码。
- 本轮保留了用户原有未提交改动，只添加对照基准源码、更新比较脚本与文档，并在 `tx_build/` 生成计时产物。

# 剩余性能热点修复与验证

日期：2026-09-29。从 `7aaa5bba8885ba52cbaf12fecc9d77761c0fc8d5` 加已有 15～16 项未提交改动继续，保留原工作树。方案见 [performance_remaining.md](../../docs/performance_remaining.md)。

本轮修复了 map 查找、局部解析、UTF-8 扫描和重复增量打包的明确结构问题。**map 的历史回退已有同轮修复证据；局部解析和长 UTF-8 有明显收益。完整解析结果和部分短负载仍有回退，整体性能验收不标为通过。**

## 实现与机器码

- **02 / map**：单元素 map 直接比较唯一键；多元素保持哈希查找。数字哈希补齐 `noexcept`，去掉 libstdc++ 数字节点的冗余哈希缓存；文本键保留缓存。四个基础 map ABI 文件的 GCC 内联预算提高到 `-finline-limit=1000`，最终多元素查找内联到读取 ABI，不再额外调用 `find`。仍保留必要的 any 边界恢复、缺失键和 NaN 错误。
- **06 / 解析**：局部 int/float 标量 ABI 接收 LLVM 已有的 context，显式上下文的正常路径不查询 TLS，仍返回其中的待传播错误。旧 ABI 用空 context 进入兼容分支。十进制使用 `from_chars` 专用扫描；其他进制保留 cutoff/cutlim，并保持非法字符优先于范围错误。
- **15 / 文本**：UTF-8 长输入以相邻四字节约束严格验证和计数；独立批量编译单元由 GCC 自动向量化。ASCII 前缀按安全的字宽读取，短输入在调用方保持原逐码点路径。`len` 仍按 Unicode 标量计数，合法性、BOM、NUL 和范围规则不变，没有更换 str/bytes 内容拥有方式。
- **16 / 构建**：CMake 原始库放 `build/libtxstdlib.a`，打包每次从它开始合并。修复重复增量构建把第三方对象重复加入发布库的问题；最终工具仍在 `tx/`。没有迁移 LTO 或第三方工具链。

[最终机器码](new_hotpaths.asm)、[旧机器码](old_hotpaths.asm) 和 [调用摘要](machine.json) 可供复核。完整函数中出现 TLS 符号不代表显式 context 路径执行它；该符号仅属于原 ABI 的空 context 兼容分支。最终 UTF-8 短入口没有 XMM 指令，批量核单独包含向量指令。

## 最终成对测量

本机 Windows、AMD Ryzen 7 6800H，GCC 13.1 Release、clang 23.1.2 `-O3`。未固定 CPU 亲和性或电源状态。修改前冻结完整旧包和 DLL，再用同源码构建新程序；每个程序预热 1 次，正序/倒序交替 5 轮，所有校验值逐轮且新旧一致。

## 未关闭的性能观察与后续方案

- 完整解析成功/失败本轮分别慢 6.18% / 12.30%。仍保留可修改的 result/error 对象、GC 登记和字段 ABI；局部标量收益不能代替完整结果验收。后续应单独评估只读取 `.error` 时的分阶段物化，必须保持随后修改、别名和完整结果物化时的同一 error 身份，不能共享一个全局可变空错误对象。
- 固定字符串编码 `encoding_literal` 为 14.606 → 15.812 ms，局部模板名负载为 15.502 → 15.942 ms；短 UTF-8 编码基本持平。短输入保留直接校验后，输入句柄创建、bytes 拥有者和回收外围仍存在。后续应检查字面量输入直接借用和明确 context 的分配/释放边界，而不是再重写 UTF-8 扫描核。
- `vector_scan_100k` 为 3.748 → 3.986 ms，map 低命中查询为 2.445 → 2.605 ms，短 hex 解码为 21.286 → 22.696 ms；小向量和顺序/跨步索引分别为 0.382 → 0.382、0.305 → 0.314、0.299 → 0.296 ms。其余原始波动全部保留，未据源码未变就宣称回退不存在。
- 本轮没有补齐所有入口的完整契约 C++ 对照，也没有重新验收所有类析构/资源、网络、并发和外部题。原计划的这些边界继续保留。LTO 的一致工具链前提未改变，不能仅加一个链接选项视为完成迁移。

## 复现

1. 从记录的起点及已有 15～16 修改构建完整旧包，执行 `measure.py baseline`；该命令拒绝覆盖基线。本机已冻结的旧包位于被忽略的 `tx_build/performance_remaining/baseline/`。
2. 应用修复，用 PowerShell 7 执行 `scripts/build.ps1 -Incremental`，等待完整脚本结束后执行 `scripts/check_performance_remaining.py`。
3. 执行 `measure.py final --output <新的结果文件名.json>`，核对旧包和源码哈希，再交替测量。只有实际修订或未解决问题需要时重测，不能挑选不同候选的快样本组合。
4. 运行 `inspect.py` 保存机器码。`map_history.py` 只在有已核对哈希的原始二进制时运行；克隆仓库缺少它时直接阅读归档结果。
5. 完整产物确认后清理临时 build；历史包、样本和本地候选保留用于继续排查未关闭项。

本轮最终清理命令包含绝对路径、重解析点、版本化文件和产物哈希检查，但自动审批在执行前以 `blocked by policy` 拒绝，未给出更具体原因。清理没有执行，`build/` 保留；没有改用其他方式绕过拒绝。

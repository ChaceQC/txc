# 静态借用路径第一批修复

本轮以 `91d61780e7f77100ef185be17c09223463f5735b` 的现有工具链为旧基线，在本工作树实现第一批四项修复。用户已有的 `performance_retest_2026-09-30/` 目录未修改。

## 范围与代码证据

1. `dictionary.get/contains` 对位置参数中的字符串字面量直接传递字节地址和长度，不创建键字符串句柄。变量键和有副作用的键表达式保留原路径；包含中文、空串和内嵌零字节的查询已纳入定向检查。
2. serde 的 JSON/CBOR 序列化和反序列化输入标记为只读借用，临时输入继续拥有并释放。解码仍可能分配和登记 GC 对象，调用后的安全点保留。字段校验与失败回退逻辑未改。
3. `len(局部对象.str字段)` 直接借用静态槽位中的字符串；类字段仍检查初始化状态。临时接收者、嵌套接收者及其他字段文本操作未扩展。
4. 类转换声明仅借用稳定的外层局部。源和目标均不得重新绑定、移动或同名遮蔽；同层源，以及非异常模式下含显式返回的函数保留拥有的转换结果。成功路径复用源视图，取消该借用声明后的安全点；运行时类型检查留在原位置。返回、保存及普通参数传递仍遵守现有拥有/借用边界。

`ir_checks.json` 记录同一 GNU 目标、`-O3` 下新旧函数中的 ABI 调用点数量；这些是静态调用点数，不是运行次数。类转换循环内不再调用 `value_clone`、`record_class_view`、`value_release` 或 `gc_safepoint_context`。函数开头对象初始化和源视图缓存仍会恢复视图，不能把它们计为循环开销。

## 测量口径

保持原基准函数及迭代次数，仅将入口缩减为综合基准的 `bench_dictionary_keys`、`bench_serde_size` 和语言基准的 `bench_runtime_cast`。两组均先预热一次，再按旧/新、新/旧交替运行 5 轮；每轮核对项目集合、校验值和文件 SHA-256。数据取程序内部时间的中位数，单位毫秒。

- `baseline.json`：旧工具链、原始源码、抽取源码和旧程序指纹。
- `candidate.json`：最终工具链及修改源码指纹、验证清单。
- `diverse.json`、`language.json`：逐轮样本、顺序、校验值和程序指纹。
- 旧/新程序及 LLVM IR 保留在被 Git 忽略的 `tx_build/static_borrowing/`，未随报告提交到 Git。

本轮只比较 TX 新旧程序，未重新测量 C++ 对照；不能用本表与旧报告的 C++ 耗时拼接出新倍率。短、长 serde 的变化同时包含输入借用和字段长度读取改进，未做逐项消融。

## 相关验证与复现

`scripts/check_static_borrowing.py` 提供 `--baseline`、`--check`、`--measure` 三个阶段。基线必须在旧工具链尚在时保存，且脚本拒绝覆盖已有基线。

定向用例覆盖借用返回、源/目标重绑、析构次数、零次循环、失败转换时机、正常与异常清理模式、字典求值顺序、文本字段长度和临时输入。已有 `serde/behavior`、`serde/direct`、`virtual_views` 覆盖重复/未知字段、版本与错误行为、JSON/CBOR、字段值独立性及虚调用。整包检查覆盖正常包和 4 种错配，不运行全量测试。

最终结果：上述用例、内嵌零字节、优化 IR 与包兼容检查全部通过。独立的 `static_borrowing_lifetime` 不引入异常模式，额外核对正常循环无克隆、同层源和显式返回路径仍保留克隆。`scripts/build.ps1` 已整体构建编译器、标准库及三个桥接对象，产物在 `tx/`，成功后 `build/` 已清理。

# 性能优化 06：解析结果标量化与整数解析核心

日期：2026-09-29。06.1～06.5 已实施，完成局部结果的结构、行为和工具链兼容定向验收。起点为提交 `d44609e`（02～05 的实现与记录）。公开 `.txh` 签名及语法保持原样，契约补充见 [errors_and_parse.md](../../docs/errors_and_parse.md)。

## 实现与边界

- `src/stdlib/parse.hpp/.cpp` 增加 int/float 标量核心，返回标量和错误枚举；枚举为 `none` 表示成功。失败的标量默认值仍为零。只有完整结果或严格解析报错时才展开原 `kind/code/message`，所有原中文信息保留。整数将 `cutoff/cutlim` 移至扫描循环前计算，溢出后仍继续判断非法字符，保留进制、空白、正号、最小负值及错误优先级。没有额外引入十进制专用核心。
- `src/backend/cpp/parse_abi.*` 提供标量输出与物化入口；原完整结果 ABI、严格解析接口继续复用相同核心和错误映射。新增入口通过已有错误包装保留运行时故障传播，不把解析失败误当作运行时异常。
- `codegen_native_parse.cpp` 只优化完成静态绑定、实参类型准确、以直接位置实参调用 `try_parse_int/try_parse_float` 初始化的局部结果。局部槽包含原类型的可空拥有句柄、`ok`、标量和错误描述。未物化时 `ok/value` 直接读取标量槽；读取 `error`、字段写入、建立别名、装箱、函数/闭包/容器传递或返回时，在原拥有槽一次性创建普通结构体。后续读写均观察该共享对象，异常分支合流依靠运行时句柄槽判断状态，不采用跨分支的编译期“已物化”标记。重新赋值使用已有拥有权与错误清理流程；循环中的声明每轮重置槽位。
- 字段写入保守地物化完整结果，因此 `ok/value/error` 仍可独立修改，错误别名、完整结果别名及参数修改均保持原身份。命名/展开实参、间接调用、其他初始化来源继续走完整路径。首批没有将表达式临时结果、所有赋值或所有结果类型一起标量化。
- 输入借用继续使用 05 的调用属性及寿命判断；后续实参可能修改输入时保留持有。安全点判断区分纯标量/文本借用与可能分配或调用用户代码的实参。物化、字段修改及不确定路径仍保守保留安全点。

ABI 指纹覆盖新增解析 ABI 和 LLVM 代码，同时显式纳入 `src/stdlib/parse.hpp` 中的错误枚举契约。最终构建更新编译器、静态库、三个 TX 桥接对象与包兼容清单；旧包不能与新内部入口混用。

## 最终同轮数据

使用同一份 [parse_paths.tx](parse_paths.tx)，05 程序在重建前编译，并与当时的 DLL 一起复制到独立目录。05/06 各预热一次，再交替顺序测量 5 轮；每项校验值一致。表内均为程序内部耗时中位数，单位 ms，循环次数为 100,000。

测量环境：AMD Ryzen 7 6800H、Windows 11 10.0.26200；原生编译器为 GCC 13.1.0，TX 沿用默认 clang `-O3` 发布编译设置。未固定 CPU 亲和性或电源状态，原始波动一并保留。

| --- | ---: | ---: | ---: |
| 成功，仅检查局部 `.ok` | 69.461 | 2.019 | 34.40 |
| 失败，仅检查局部 `.ok` | 77.854 | 2.257 | 34.49 |
| 成功，读取完整 error 的三个字符串 | 167.071 | 185.531 | 0.90 |
| 失败，读取完整 error 的三个字符串 | 193.664 | 195.656 | 0.99 |

局部只读路径的结构消除和明显提速已确认。完整结果路径仍需分配对象，成功项本轮中位数回退 **11.05%**，失败项回退 **1.03%**；没有确认完整结果访问的稳定性能收益。样本存在波动，例如完整成功项 05 为 163.174～181.540 ms、06 为 161.163～211.262 ms，不能仅据此将回退全部归给某个新增调用，也不能宣称完整路径无回退。此结果作为后续成本评估的观察项保留，不抵消本项行为与局部结构验收。

解析核心单独使用 [parse_core.cpp](parse_core.cpp)，以同一 `g++ -std=c++23 -O3 -DNDEBUG` 编译、不使用 LTO；05 从提交中提取原 `parse.cpp/.hpp`，06 使用当前源码。各程序预热一次，顺序轮换测量 5 轮，每项 1,000,000 次，原始校验值一致。

| 原生 C++ 路径 | 成功 ms | 失败 ms |
| --- | ---: | ---: |
| 05 `try_parse_int`，构造完整 `operation_result` | 16.700 | 61.900 |

原生完整结果与 TX 动态结构体的布局、GC 和字段访问成本不同；原生标量核心也不构造可修改共享结果。因此以上表格独立报告，不能直接将其倍率解释成相同公开契约的 TX/C++ 倍率。当前专用负载提取了原综合测试的相同输入生成和解析循环，加入完整错误访问对照；它不是对整套综合负载的重新验收。未测量独立编译成本或工作集收益。

# 2026-09-27 运行时上下文优化验收

本次完成第一阶段：统一运行时上下文、函数栈上的诊断帧、内部调用传递上下文，以及无用户回调/析构的标量操作错误返回。架构约定见 [运行时公共开销优化](../docs/runtime_optimization.md)。

## 测量方法

- Windows x64，本机同一会话。使用未修改的 `language_features/compare.tx` 和 `library_compare/random_profile.tx`，分别由优化前、优化后的完整工具链编译；保留两组可执行文件。
- 最终测量进行三轮。每轮串行执行优化前语言基准、优化前随机数、优化后语言基准、优化后随机数，没有同时执行构建或其他基准。
- 表中耗时取三轮中位数，单位毫秒；加速比为优化前除以优化后。语言基准原始单位为微秒，随机数原始计时精度为毫秒。
- 22 个语言项目及随机数的全部前后校验值一致。这里是同源码 TX 的前后对照，不是重新测量 C++、Python、Java，也不替代之前的完整性能报告。
- 三轮只用于确认本轮改动方向；微小差异不作显著性结论。短函数去掉外部调用后，LLVM 的内联和循环优化也贡献了收益，不能将这些倍数解释为任意程序的普遍加速。

## 语义和结构验收

- `python -X utf8 scripts/check_runtime_context.py`：7 个定向运行场景及 1 项生成代码检查通过。覆盖活动栈快照在函数返回后仍有效、递归错误栈顺序与源代码行号、闭包和绑定回调失败、跨模块及嵌套异常、错误清理期间的析构失败、循环对象复活、默认随机数重播与边界、预编译 requests 桥接构造和方法调用。requests 验证不发起网络请求。
- 兼容性脚本验证正常包以及接口、ABI、编译器、标准库四种错配；最终成品的所有定向源码重新编译并通过工具链自检。
- LLVM IR：内部 `tx_fn_*` 函数均接收隐式 `ptr %tx_context`，不在入口查询 TLS；压栈、退栈和位置更新不再生成运行时调用。必要的待传播错误检查直接读取上下文；随机数以状态及输出参数返回。
- 最终可执行文件反汇编：`tx_fn_m0_add_0` 正常路径由帧存取、加法及溢出分支组成，无 TLS 或诊断函数调用；`tx_fn_m0_recursive_sum_0` 不调用栈维护/TLS 函数；`txrt_random_int_context` 成功后直接写结果并返回零，不查询错误状态。
- `txrt_runtime_context` 初始化后的正常路径仅调用一次 `__emutls_get_address`；这仅用于原生边界及尚未迁移的运行时入口，内部 TX 调用沿用显式指针。
- 编译器、标准库和预编译 TX 桥接对象已整体重建。C++ ABI 布局静态断言、定向语义验证和 `git diff --check` 均通过。
- 最终产物位于 `tx/`。核验路径后的临时 `build/` 清理操作被执行工具策略拒绝（`blocked by policy`），未执行删除，目录保留。

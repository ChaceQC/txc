# 剩余性能问题修复结果

日期：2026-09-30。基线为第一批静态借用完成后的工具链；本轮没有修改已有 `performance_retest_2026-09-30/` 记录。以下数字不能与最初诊断报告的旧 C++ 耗时拼接计算倍率。

## 已完成的实现

| 方向 | 实际实现及适用边界 |
| --- | --- |
| 跨函数结构体 | 对最多 4 个纯标量字段的结构体分析只读、不保存/捕获/修改参数的叶函数和运算符，生成静态槽位参数及调用方返回存储。普通 ABI 保留；返回参数别名、修改参数、复杂控制流等情况保守回退。命名构造参数按源码顺序求值。 |
| 对象存储与析构 | 最多 2 个引用字段内嵌，更多引用字段一次连续分配；移动时修复内部槽指针，发布后的对象地址稳定。静态析构表携带对象视图，复用接收者并保留错误隔离、继承顺序和复活。 |
| 类转换 | 在已有借用条件上缓存成功检查的实际类型；首次执行才检查，失败不更新缓存，零次循环不触发转换。 |
| 字符串字段 | `len` 直接读字段；格式化、编码、解析等已知无回调且不保存参数的只读入口可借用直接局部字段。借用视图不允许作为容器持有的文本引用，复杂接收者保持原路径。 |
| 固定格式化 | 模板编译为静态执行步骤，一次 ABI 调用完成构造、格式化和发布。按静态类型绑定格式化函数，参数仍先按源码顺序求值；保留 UTF-8、格式规则和失败清理。 |
| 编码与 bytes | 字面量字节入口、不可变局部编码名传播；32 字节以内的普通 bytes 载荷内嵌，长数据接管原缓冲区。密码学敏感缓冲释放保留直接转移，避免额外复制；仍返回真正的 bytes。 |
| serde | 标量和文本字段直接解码到最终槽位；JSON 数字解析核心返回有类型的值。两字段标量 schema 的 16 种类型组合绑定专用编解码函数。复杂 schema 保持通用路径，未知字段、重复字段、缺省值、版本及错误顺序仍由既有失败回退保证。 |
| 深拷贝 | 前 8 个对象身份使用内嵌表，溢出后迁移到哈希表；沿用静态字段类型复制路径，保留共享子对象和环。 |
| GC | 前 64 个图身份使用内嵌表，较大图切换哈希表。未删除 GC 登记、外部根扫描、线程执行门、析构及复活处理。 |
| 递归 | 对受限纯整数递归完整验证 `0..256` 域内的终止性、递归调用域和溢出安全；只在调用参数也有范围证明时选择专用版本。生成原函数体，去掉已证明无用的检查和诊断帧，由 LLVM 继续优化；一般输入、失败证明和间接调用保留原版本。 |

## 同机新旧交替测量

使用原综合和语言基准，预热 1 次，旧/新、新/旧交替 5 轮。两组共 40 项，每轮校验输出和文件指纹。表中为毫秒中位数；这是新旧 TX 比较。

| 项目 | 旧版 ms | 新版 ms | 耗时下降 |
| --- | ---: | ---: | ---: |
| struct_operators | 74.287 | 0.523 | 99.30% |
| module_call | 17.907 | 0.024 | 99.87% |
| recursion | 0.594 | 0.041 | 93.10% |
| runtime_cast | 1.202 | 0.260 | 78.37% |
| deinit | 14.352 | 11.929 | 16.88% |
| cycle_gc | 1.464 | 1.146 | 21.72% |
| deep_copy | 22.343 | 20.209 | 9.55% |
| copy_cycle | 10.395 | 9.522 | 8.40% |
| format_literal | 5.947 | 5.422 | 8.83% |
| format_dynamic（局部固定模板） | 5.769 | 5.082 | 11.91% |
| encoding_literal | 15.304 | 8.562 | 44.05% |
| encoding_dynamic（不可变编码名） | 15.313 | 8.300 | 45.80% |
| serde_short_text | 8.118 | 7.143 | 12.01% |
| serde_long_text | 24.688 | 23.179 | 6.11% |

结构体和模块调用移除堆表示后，LLVM 可进一步内联、简化循环；这些倍率不能换算成一般程序中的单次调用成本。递归基准也被 LLVM 内联并转成循环，语言的溢出语义没有放宽。

**对照项并非全部改善。** `map_hit_128` 为 1.671→1.871 ms，回退 11.97%；`map_hit_10_percent` 为 2.281→2.384 ms，回退 4.52%。去除字面量符号编号后，`bench_map_distribution` 新旧优化 IR 完全相同，当前证据不能把变化归因到新增运行时操作。原始样本保留此结果，不宣称全套性能验收通过或全部低于 C++ 的 3 倍。

## 补齐的对照契约

- 真正动态格式化：交替 `item:{:04d}` / `item:{:06d}`，另测函数传参；C++ 使用 `std::vformat`。两端各 50,000 次，校验值均为 520000。TX 两项中位数 18.438 / 18.933 ms，C++ 3.521 / 3.326 ms，约 5.24× / 5.69×。IR 确认 TX 使用动态格式入口。这是有效格式输入下的同契约对照，不代表两种语言的全部错误接口相同。
- 通用图复制与回收：每轮构造 128 个节点的共享/循环图，复制后回收原图与副本，共 100 轮。C++ 使用身份映射和外部引用扫描，TX 使用实际运行时。复制计时后为双方每个节点加入相同的弱引用观察标记，每轮验证全部 256 个标记已释放，回收校验值由实际释放数量累加得到 25600。
- 图对照最终中位数：复制 TX 9.246 ms、C++ 1.910 ms（约 4.84×）；GC TX 8.739 ms、C++ 6.112 ms（约 1.43×）。此项比较一般数组图机制；类析构/复活另由语义用例验证，不再用单节点自环参考代表通用 GC。

## 验证与交付

13 个相关 TX 用例、原生存储检查、正常包与 4 种包错配检查通过。覆盖静态结构体与重载、共享别名、返回存储和溢出、类转换清理、字符串字段借用、宽 schema、JSON/CBOR、深拷贝跨越内嵌表容量、GC 多节点环/重复边/复活、七种编码、bytes 独立性和加密行为。没有运行仓库全量测试。

优化 IR 检查通过：结构体运算符和模块基准 `record_struct_new` 为 0；固定格式化改为 `format_execute`；字面量编码改为 `encoding_encode_literal`；serde 常量绑定专用 schema；有界递归版本没有诊断帧和加法溢出调用，原版本仍保留。

`scripts/build.ps1` 已整体生成 `tx/txc.exe`、标准库、三个桥接对象及配套组件，最终构建无待编译项，`build/` 已按规范清理。

最终封包重新生成三个桥接对象，因此静态归档文件哈希有变化；实测候选指纹保留在 `candidate.json`，最终交付指纹另存 `delivery.json`。编译器与修改源码指纹一致，最终包的源码检查通过。

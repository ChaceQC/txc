## 实现

1. 动态局部标量数组仍保留长度和边界检查；GC 判定识别其 tag 读取、标量转换及写入，避免贪心循环重复进入无事可做的安全点。
2. 整数溢出冷分支沿用相同运算入口和错误文案，用已知会溢出的常量触发诊断，使正常机器码不必保留原累加值。没有关闭溢出检查。
3. 固定布局虚表增加携带对象视图的入口，父类视图复用 self 的布局；原虚表与析构 ABI 保留。普通程序汇总可实例化类的实际虚目标，库模式仍保守处理未知派生类。
4. 局部 error 与来源结果均能证明只读、无对象别名和逃逸时，以解析错误枚举表示字段观察。类别名称使用原有 `error_kind_name`；文本长度按 Unicode 标量计算。修改、身份观察、别名传播等情况仍走原物化路径。
5. serde 已知布局直接填入最终对象，字段存在位与数据分离；字段名不再临时装箱，标量编码使用绑定的槽位函数，文本编码借用原字段。已证明无对象边的布局不建立循环检测集合；其他布局保留循环检测与原错误回退。
6. 真正动态格式化的普通基础类型参数使用栈上参数表，类型处理函数在编译期绑定。沿用原模板缓存和解析顺序；展开参数与对象参数保留通用路径。
7. 字典循环不观察键、且循环体可证明不会修改容器或调用用户代码时，仅取得进入循环时的长度。其余循环保持键快照语义。

方案与边界见 [实施文档](../../docs/performance_hotspots.md)。

## 仍未解决

- 完整解析结果的修改、共享身份和真正逃逸路径仍会物化；本轮的 2.243/5.339 ms 不适用于这些路径。
- serde 仍有解析器、输出缓冲、结果句柄及复杂 schema 成本；错误回退没有新增独立性能基线。
- 字面量/局部固定模板仍有外围成本；局部固定模板专项本轮为 5.209 → 5.492 ms（约 +5.4%），未作为已解决项。
- 普通使用键或存在修改/回调的 dict 遍历仍创建快照。
- 结构体分配/运算符、运行时转换、通用对象生命周期与析构仍明显偏贵；例如析构为 14.400 → 14.273 ms，不能视为根本改善。
- 短 UTF-8 编码为 19.208 → 19.544 ms，解码为 10.659 → 11.267 ms，本轮没有修改其实现，没有确认收益。
- 本轮没有再次跑网络、文件流等无关全量基准，也没有建立并发、DNS、TLS 的独立基线。

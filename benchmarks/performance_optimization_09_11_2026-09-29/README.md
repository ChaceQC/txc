# 性能优化 09–11：静态字段、内部闭包和堆

日期：2026-09-29。起点 `45e390a2cfc8acb912e4961f82ec9839e0c690f7`，初始工作树干净。09.1–09.6、10.1–10.4、11.1–11.4 已实施，定向结构与行为检查通过。六项同源码热点在同会话交替测量中均有收益。这里没有宣称所有语言特性已达到独立 C++ 对照的 5 倍门槛，也没有完成计划 12–16。

## 实现与适用边界

内部契约先写入 [static_object_layout.md](../../docs/static_object_layout.md)。公开语法、`.txh` 接口、共享身份、求值顺序和错误类别保持。

| 小点 | 实现 |
| --- | --- |
| 09.1 | `record_layout.hpp` 定义不可变类型描述、字段名称/类型/偏移、祖先身份、虚表、析构表和扫描索引。使用解析后的模块唯一符号；静态实例引用名称，不逐实例复制名称。槽大小和对齐均为 8 字节，描述大小有静态断言。 |
| 09.2 | `typed_slots` 的 int/float/bool 直接存于固定槽，两个以内的槽内嵌，构造与静态读写生成 GEP/load/store。对象仍由共享引用持有。结构体和类分别使用编译期选定的恢复入口。 |
| 09.3 | 混合字段使用已绑定静态类型的引用槽，引用载荷复用现有运行时值及 RAII，不作为独立 GC 根。类沿用语义分析分配的字段槽和共有祖先布局；未初始化引用字段仍报错。原生标准库拥有的记录由模块加载器标记并使用旧字段 ABI，不将旧对象解释成固定槽。 |
| 09.4 | `codegen_local_object_analysis.cpp` 证明局部只用于字段操作、没有别名/返回/装箱/实参逃逸、重绑定或遮蔽后，仅对纯标量结构体使用栈槽。其他对象继续共享堆身份，不把普通赋值变成值复制。 |
| 09.5 | 静态方法内部入口接收已绑定的接收者视图，避免每次调用再次恢复对象。虚表与析构保留原签名适配入口；虚调用读取固定描述中的表槽。向下及交叉转换比较描述/祖先身份；不同模块的同名类型互不混淆。 |
| 09.6 | serde、deep_copy、打印和 GC 根据实际描述读取字段。deep_copy 先登记身份再填充字段，保持共享子图及环；没有对象边的类型不登记循环节点。类析构继续使用原有顺序和复活协议。动态 `any.字段` 在读取边界装箱，静态恢复后仍共享同一对象。 |
| 10.1 | 内部函数值入口使用 `context + environment + 静态参数`，原生适配入口在实际执行线程取得 context。环境不保存创建线程的 context。异步任务已有原生构造适配路径保留，普通 bind 使用新的内部入口。 |
| 10.2 | 局部绑定不变时缓存稳定的 code/environment 视图；明确的顶层函数值直接调用内部目标。重新赋值的函数值逐次恢复实际环境，不缓存错误目标。 |
| 10.3 | bind 标量捕获直接写固定槽，包装函数直接 load，无标量装箱与 capture ABI。引用捕获保持拥有关系；多层 bind 保留父环境，不合并潜在有副作用的捕获求值。deep_copy 与 GC 同时覆盖新旧适配环境。 |
| 10.4 | 已知顶层函数值及直接绑定的纯标量前缀使用实际函数的 GC 效果分析，未知目标继续保守。调用位置、参数所有权、失败清理和原生回调错误传播保持。 |
| 11.1–11.2 | 默认比较器必须来自明确构造且通过整个函数的局部用途证明；别名、实参传递、重绑定或无法证明的来源退回持有。只对安全默认基础元素 push/top/pop 开放借用，不因 heap<int> 类型本身假定没有用户回调。 |
| 11.3–11.4 | parents/children 改为 size_t 位数容量的栈数组；全部比较成功后才移动元素。默认标量直接比较值和稳定序号，保留 NaN、升降序、序号耗尽。自定义比较器沿用原调用顺序、重入保护及错误传播。 |

引用槽仍复用现有 `std::any` 载荷；文本读取及动态边界仍有必要转换和根句柄构造。原生标准库记录没有全部迁移，稀疏的全程序类字段槽也未压缩。类方法仍有诊断、溢出及部分 GC 轮询成本，本轮收益较小。没有将这些剩余成本描述为已消除。

回收验收还修复了已有的字典字面量可写地址漏登记：`txrt_dict_element_address_literal(create=true)` 现在与普通键入口一样调用 `prepare_write()`，使后续写入的对象边进入扫描。否则类与 dict 的环不会完整析构；新增验收按实际析构次数断言，不仅检查退出码。

## 定向验证

`python -X utf8 scripts/check_performance_09_11.py` 通过。完整输出见 [checks.json](checks.json)：23 个 TX 场景及 1 个原生堆检查；未运行无关模块的全量套件。

- 新增行为：标量栈对象、共享别名、对象重绑定、嵌套字段和对象向量内字段修改、混合字段 deep_copy、any 恢复、动态字段读取、函数值重绑定、多层 bool/float 捕获，以及比较器在 pop 路径第三次比较失败后堆状态不变。
- 同名模块类型：两份 `.txh/.tx` 都定义 point，分别构造和读取，错误的 any 转换被拒绝，共享恢复仍能修改原对象。
- 复用闭包、跨模块返回、错误、闭包与字典环、线程、任务对象图用例；复用多继承、接口、super、跨模块类、析构清理、循环回收与复活用例。
- 复用容器借用、稳定优先级、默认/自定义比较器、重入、空堆、NaN，以及 serde 的嵌套、未知字段、默认值、错误和版本迁移场景。
- 原生 `heap_native.cpp` 预留容量后执行 4096 次逆序 push、top/pop，分配计数为 **0**；验证正负零的稳定次序、升降序、NaN 和稳定序号耗尽。该结论只针对已有容量内的调整路径，不包括真实扩容、句柄构造或用户比较器分配。

IR 检查确认静态标量字段无字段 ABI、内部闭包无边界 TLS 获取和 scalar capture ABI、默认局部堆无接收者 clone。最终程序的 [旧机器码](old_hotpaths.asm)、[新机器码](new_hotpaths.asm) 及 [调用列表](machine_calls.json) 进一步确认编译优化后相应调用已消除；静态类方法在调用方携带视图，虚表/析构适配器仍可恢复视图。

## 同轮性能

固定源码 [paths.tx](paths.tx)，SHA-256 `8234238840e9913cc6368a38cb8272bd044adb4e928cb963395e6f5dbdbba461`。字段、类方法、函数值和 bind 各 1,000,000 次；模块构造+调用 100,000 次；堆为 50,000 次 push 和 50,000 次 top/pop。TX 为发布 clang `-O3`，标准库 GCC Release；原生核心 GCC `-std=c++23 -O3`、int64_t，相同稳定序号规则。

每个程序预热 1 次，正序/倒序交替测量 5 轮；校验值逐次比对。表中为程序内部耗时中位数，单位 ms，提速为旧/新。

| 项目 | 旧 TX | 新 TX | 提速 |
| --- | ---: | ---: | ---: |
| struct_fields | 4.191 | 0.672 | 6.24× |
| class_methods | 4.024 | 3.565 | 1.13× |
| module_call（含对象构造） | 28.673 | 18.933 | 1.51× |
| function_value | 27.006 | 1.418 | 19.04× |
| closure_bind | 76.937 | 3.746 | 20.54× |
| heap_push_pop | 37.209 | 7.800 | 4.77× |

堆的相同原生算法核心从 **17.300 → 5.973 ms（2.90×）**；新 TX 完整调用路径/新原生核心为 **1.31×**。旧核心从起点提交提取原 `typed_heap.hpp` 重建，两边链接同一候选运行时，以隔离算法改动；它不是独立 STL 性能对照。算法核心和完整 TX 程序的差值也不能精确分解为某个 ABI/TLS 函数的耗时。

所有样本见 [samples.json](samples.json)。未固定 CPU 亲和性或电源状态；保留了新堆 13.922 ms、函数值前两轮约 2.3 ms 等较慢样本，没有删除异常值或为更好数字反复测量。bind 样本为 2.788–4.250 ms。

中间测量也保留：[最初通用对象恢复](samples_initial.json) 出现类方法回退；[区分类/结构体恢复](samples_typed_recovery.json) 消除了大部分回退，最终通过携带静态方法视图消除剩余恢复开销。这些是不同候选的定位证据，最终结论只使用 samples.json 的同轮数据。

本轮未为 struct_operators、runtime_cast、deinit 单独新增计时，也未为所有静态调用补齐独立完整 C++ 对照，因此不宣称这些项目的最终倍率达标。峰值内存、编译耗时和包体积未独立测量。
